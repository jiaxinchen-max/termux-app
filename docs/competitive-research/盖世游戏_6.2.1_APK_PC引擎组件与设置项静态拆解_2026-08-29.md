# 盖世游戏 6.2.1：PC 引擎组件与设置项静态拆解

## 1. 样本与结论边界

| 项目 | 值 |
|---|---|
| APK | `盖世游戏_6.2.1.apk` |
| 包名 | `com.xiaoji.egggame` |
| versionName / versionCode | `6.2.1` / `138` |
| minSdk / targetSdk | `29` / `36` |
| ABI | `arm64-v8a` |
| SHA-256 | `93bc8cf8043d524ca78b90b574a0c4879a7bf472a32dc8ba3504f4f17d0dbdaf` |
| 分析方式 | 仅静态解包、资源解码和 DEX 结构分析；未安装、未执行 APK |

PC 模拟器不是完整编译在主 APK 内，而是动态插件：

```text
主 APK
├── 游戏设置持久模型
├── 组件索引 API 和组件元数据模型
├── 下载/安装任务编排文案与状态
├── PC 引擎插件下载、校验、staging、提交、回滚
├── 插件 Host Activity / Service
└── com.xiaoji.egggame.plugin.pcengine（动态 APK）
    ├── Wine/X11 运行界面
    ├── PC 设置界面
    ├── 依赖安装界面
    └── PC 引擎 Bridge Service
```

因此，本报告能完整恢复主 APK 持有的设置结构、启动协议、组件索引结构、组件状态和大部分转译器选项；不能从该 APK 单独恢复服务器当前下发的 Wine、ImageFS、DXVK、VKD3D、Box64、FEX 等具体版本行，也不能恢复动态插件内部独占的 UI。

插件安装输入包含候选 APK 路径、SHA-256、插件 ID、schemaVersion 和 ABI。主 APK 对候选包执行校验，安装到 staging，随后 commit；异常时 rollback，并持久化当前激活插件身份。这套机制与普通模拟器组件下载是两层独立链路：插件 APK 使用 SHA-256，Wine/ImageFS 等组件元数据使用 MD5。

| 值 | 说明 |
|---|---|

状态枚举：

```text

  \--------------------------------> NeedUpdate
```

`NeedUpdate` 是版本比较结果，不是严格位于安装流水线中的单向状态。组件还存在独立的 `broken` 记录，UI 文案为“已损坏（点击重装）”。

### 6.6 安装编排状态

从内置文案可恢复以下任务链：

```text
获取游戏配置
  -> 检查环境和 ImageFS
  -> 检查虚拟容器
  -> 检查通用组件
  -> 检查 Steam 客户端/Steam 组件（按需）
  -> 检查依赖组件状态
  -> 下载主包/子包
  -> MD5 校验
  -> 解压
  -> 执行安装步骤/EXE/注册表动作
  -> 应用推荐游戏设置
  -> 启动游戏
```

可见失败类型包括：

- 未配置容器、找不到兼容层、未配置 ImageFS
- 游戏配置下载/获取失败
- 依赖组件下载失败
- 组件解压失败、安装失败或安装不完整
- 容器安装失败、返回错误码或进度未完成
- 虚拟容器检查失败
- 任务运行时禁止追加或清空任务

## 10. 对 Games 模块组件系统的直接映射

按 APK 证据，组件注册表至少需要以下稳定维度：

```text
ComponentDescriptor
├── identity: id, name, displayName, type
├── version: version, versionCode, framework, frameworkType
├── artifact: fileName, fileSize, downloadUrl, fileMd5
├── subArtifact: subFileName, subDownloadUrl, subFileMd5
├── presentation: logo, blurb, upgradeMsg
├── flags: base, isSteam
├── dependency: dependencies, steps, hasExeInstall, effectRegistry
└── localState: None/Downloaded/Extracted/NeedUpdate/INSTALLED/Broken
```

不要把 `container`、`imageFs`、`gpuDriver`、`dxvk`、`vkd3d`、`translator` 合并为同一种 UI 开关。它们共享下载仓储和状态机，但拥有不同的兼容性约束、默认继承规则和运行映射。
