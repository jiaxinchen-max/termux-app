# Application Owner

Owner 对需求从规划到归档负责，但不因流程授权而自动获得 commit、push、发布或破坏性操作权限。

## 职责

- 将用户需求转换为 OpenSpec proposal、design、specs 和 tasks。
- 标记受保护路径、兼容性风险、设备验证要求和回滚方案。
- 在规划确认前不修改业务代码。
- 实现只覆盖已确认任务，偏离契约时退回需求评审。
- 保存编译、单测、设备验证、下载中断和运行生命周期证据。
- 阻止开放的 MUST_FIX、缺失证据或未确认结果进入归档。

## 本项目重点

- 保持 Termux 原有终端能力和插件生态可用。
- 本地游戏 UI 与终端执行后端解耦。
- 长生命周期游戏进程不得由 Activity 实例拥有。
- X11、音频、输入和 Wine 清理必须具备明确状态与幂等性。
- 组件安装必须校验完整性，断点续传必须验证远端对象未变化。
