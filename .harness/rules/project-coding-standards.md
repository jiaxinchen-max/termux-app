# Project Coding Standards

- 保持现有 Java 8、AndroidX、XML/ViewBinding 技术栈；引入 Kotlin/Compose 必须单独批准。
- 新 UI 放在独立包，禁止将本地游戏业务继续写入 `TermuxActivity`。
- UI 线程不得执行文件扫描、下载、解压、校验、prefix 初始化或进程等待。
- shell 参数必须逐项安全引用；不得拼接未经校验的游戏路径或用户参数。
- 不通过解析终端屏幕文本判断任务状态。
- 任务状态必须持久化，Activity 重建和应用进程恢复后可重新观察。
- 下载使用临时文件和原子替换；断点续传校验 Range、对象版本和最终摘要。
- 启动与清理必须幂等；异常退出后不得残留错误锁、音频服务或错误的输入状态。
- 修改 X11/NDK 代码必须提供对应模块编译和至少一个真实输入/显示验证。
- 保留用户已有工作树修改，不重写无关文件。
