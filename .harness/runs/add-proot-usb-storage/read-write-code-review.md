# USB 读写增量源码复核

方式：主代理直接源码自审，按 stellios-code-review；没有独立审查者。结论：允许保存进度和手动验证，无未解决 MUST_FIX；不等于产品最终验收。

核对范围为模式持久化/启动合约、四类会话 guest 总线/路径/ABI、静态保存事务、Android 查询边界、WebDAV 现有写接口、设备服务释放、凭据与 APK 资源。运行服务延续按会话拥有的清理，不引入全局 kill/启动预检；七个原有 dirty 子模块未修改/暂存。

已修复：未授权设备从文件管理器连接失败后保留 App 授权入口；读写授权不能自动挂载；Android 只读挂载/过渡/未知状态均拒绝；文件服务刷盘失败不能在后续弹出误报成功。测试覆盖真实 Manager 的轮询/授权、GIO 忙和文件服务非零退出分支。

已知限制：公开 StorageManager 查询不与底层 USB 接口 claim 构成原子操作，不能映射到单个 USB 盘，因此要求全部可移动卷卸载；不声称自动/强制系统卸载。实际固件的卷可见性、系统卸载后 USB 仍可访问以及实体 SCSI 刷盘行为必须用实机验证。新 APK 未替用户安装，四桌面完整 GUI 尚未验证。镜像写入/重新打开成功仅证明文件桥接链路。

回退：停止桌面、设 USB off 并保存；回退本次实现提交，不删除已有依赖和用户数据。产品文档与基线待最终验收；缺失 Harness 严格脚本不记为通过。
