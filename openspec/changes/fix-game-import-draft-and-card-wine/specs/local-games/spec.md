# 游戏导入与 Wine 展示增量规范

## ADDED Requirements

### Requirement: 新导入必须在显式保存后加入正式库
系统必须将未保存的导入视为草稿；Native 与 PRoot 都必须在首次显式 Save 才发布正式游戏记录。

#### Scenario: 放弃新导入
- **WHEN** 用户选择 EXE 后没有 Save，选择 Discard 或退出未保存导入
- **THEN** 游戏库不出现该次导入卡片，且不启动环境准备任务
- **AND** 外部游戏文件、共享运行时、共享 prefix 和下载缓存保持原样

#### Scenario: 页面往返与首次提交
- **WHEN** 用户经过组件选择或屏幕重建后首次 Save，游戏字段可能未改动
- **THEN** 系统发布准确的游戏及所选 Wine 配置，库中仅有一张该次导入卡片，再运行原有准备流程

#### Scenario: 提交失败与准备失败
- **WHEN** 首次保存的配置持久化或正式记录发布失败
- **THEN** 系统报告错误并且不发布游戏卡片
- **WHEN** 正式记录发布后环境准备失败
- **THEN** 保留已保存记录，禁止启动并显示失败，不执行 wineboot、重建或回退

#### Scenario: 放弃既有游戏修改
- **WHEN** 用户对已保存游戏选择 Discard
- **THEN** 原有游戏和已保存运行配置保留，当前未保存修改不生效

### Requirement: 卡片必须显示已保存的 Wine
卡片和列表必须显示当前正式运行配置对应的 Wine 名称与版本，并保留后端信息。

#### Scenario: 保存 Wine 选择
- **WHEN** 用户将 Wine 9.3 切换为 Proton 11 并保存后回到游戏库
- **THEN** 卡片与列表显示 Proton 11；未保存或 Discard 的选择不影响展示

#### Scenario: 本地组件和未知展示名
- **WHEN** 已保存配置使用本地安装 Wine
- **THEN** 展示对应组件名及版本；无法解析展示名时展示真实配置标识，不替换为默认 Wine
