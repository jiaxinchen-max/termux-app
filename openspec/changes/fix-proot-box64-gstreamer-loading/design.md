# GStreamer 依赖修复设计

## 根因假设与证据

Box64 的 GStreamer 包装层通过 gtkclass.c 桥接 GObject 类；源文件名称不等于 GTK 动态依赖。默认 0.4.4 声明非必要的 libgtk-3.so.0，缺失时会输出依赖初始化错误。补丁精确改为 libgobject-2.0.so.0、libglib-2.0.so.0、libgmodule-2.0.so.0，保持包装 API 和原版本不变。

实测修正原先假设：编译机 Debian 13/GStreamer 1.26.2 的原版虽报 GTK 错误，仍通过核心流水线、自定义元素回调和 WMV2 解码；候选通过且不再报 GTK 错误。Android App 域的 Ubuntu 26.04.1/GStreamer 1.28.2 中，原版和候选同样均能完成 WMV2 解码。因此该依赖缺陷确实存在，但尚不能将其认定为此前 Wine 播放失败的根因。

真实 App 域复测采用现有 Proton 11、隔离前缀及 App 后端虚拟桌面命令，原版/候选 PE64 均完成 WMV2 播放与 COM 释放；候选 PE32 也完成播放与释放，私有会话受控关闭后原始退出码为 1。原版 PE32 在 180 秒内未进入 GStreamer，单次启动差异不能证明依赖补丁修复了 32 位启动。未使用虚拟桌面的早期探针窗口失败已由完整后端命令的通过结果纠正，受超时清理干扰的早期记录不用于验收。

结论限定为已确认的依赖缺陷及公开媒体冒烟范围，不覆盖全部格式、Media Foundation、真实游戏或 Java 控制器完整流程。Proton 经 Box64 的原生包装链与 Hangover 的 ARM64 Unix 链分别看待，不能因同名库存在就认为实际加载成功。

## 编译机与构建边界

使用现有编译机与历史 SDK，先读取此前 box64-0.4.4-proot-results.tar.xz 的 CMakeCache、日志和测试。独立候选目录保存原始源码、补丁、构建选项、编译器版本、原/新二进制摘要以及日志；不覆盖原有编译目录或归档。沿用 Release、ARM64 dynarec、BAD_SIGNAL、64KiB LOAD 对齐以及 /lib/ld-linux-aarch64.so.1；不引入 Native Termux 路径。云端不构建组件。

## 验证、保护与回滚

同一无 GTK 测试根和相同探针分别运行原二进制与候选。检查 GLib/GObject 加载和类型桥接，执行 GStreamer 真实音视频流水线，检查实际输出及自然退出；再条件允许时使用公开 DirectShow 的 PE32/PE64 探针。复用历史 probe，保留播放与 COM 释放分开的结果，不修改生产退出逻辑。编译机测试与 Android App 验收分别记录。

没有保护路径注册表；影响限定构建输入与候选产物。原组件、索引、镜像及 APK 保持。回滚直接弃用独立候选及撤销源码补丁，保留历史存档。Harness 引导、严格脚本或 OpenSpec CLI 缺失时如实记录，不伪称严格门禁通过。

## 已批准的六候选发布设计

0.2.8 固定提交 8545d0505f274554561ca30e1839027dd7be783a；0.3.8 固定 81c56d7155cdd7a4c49173a2fe4d7bdd87698683；0.4.4 沿用已有固定提交。依版本生成最小补丁并核对源码差异，Native 解释器/RUNPATH 使用 /data/data/com.termux/files/usr/glibc/lib，PRoot 解释器使用 /lib/ld-linux-aarch64.so.1 且无 Native RUNPATH。已验证的 PRoot 0.4.4 候选可复用，其他目标在原 SDK 独立构建。

使用各组件当前公开归档为基线，只替换 Box64 ELF，保持所有支持库、归档路径、权限及链接；每项记录输入输出摘要和成员对照。保留原归档供明确回滚，发布使用现有组件标签与同名资产。组件 ID、versionName、默认值、URL、选择和已装版本策略保持；更新索引大小、摘要及依赖修复说明，索引修订沿用现有值以符合原地更新要求。组件仓库两个索引以当前 App 索引为权威同步，非本次资产不做二进制替换。原标签的旧摘要附件如存在须同步，避免新资产与旧校验表冲突。

在编译机对每个目标执行 ELF 加载器/对齐、版本和静态/动态 x86 冒烟，以及 GStreamer 核心、元素回调和 WMV2 解码。Android 验证在真实 App 域运行，具备的目标环境分别核对，不把 SDK/QEMU 当完整产品验收。任何旧版本新增功能性回归须停止该项发布并保留证据。发布前完成直接自审和适用回归，发布后从公开 URL 全量下载核对大小及 SHA256，然后提交组件仓库与 termux-app。Harness 缺失仍记未通过；发布权限来自用户本轮指令。
