## ADDED Requirements

### Requirement: GStreamer 包装层使用实际运行依赖

系统 SHALL 使默认 PRoot Box64 的 GStreamer 包装层依赖 GLib、GObject 和 GModule，不因非必要 GTK 缺失阻止视频链路。

#### Scenario: 无 GTK 的容器初始化 GStreamer

- **WHEN** 容器存在对应 ARM64 GStreamer、GLib 及所需媒体插件且没有 GTK
- **THEN** 包装层不请求 libgtk-3.so.0，真实流水线运行结果和退出状态可验证

### Requirement: 沿用编译机与隔离验证

组件 SHALL 在用户指定编译机的既有环境中编译，读取历史补丁与存档，保持默认版本与文件命名，原始资源不被覆盖。

#### Scenario: 回移上游依赖修复

- **WHEN** 固定源码尚不包含 PR #4528
- **THEN** 仅回移依赖声明，在独立目录生成候选及来源记录，不自动发布或改索引

#### Scenario: 媒体测试仍失败

- **WHEN** 构建或媒体任一层失败、超时或退出未完成
- **THEN** 原始失败被保留，不将编译成功、库存在或单个格式成功描述为全部 Wine 媒体兼容

### Requirement: 当前六项候选原地发布

经本轮用户批准，系统 SHALL 为 Native 和 PRoot 的 0.2.8、0.3.8、0.4.4 六项分别修复不必要的 GTK 依赖，保留各版本架构、加载路径、支持库及当前命名，原地更新现有分发资产并同步两个仓库。

#### Scenario: 六项资产完成核验

- **WHEN** 每项构建、成员对照及适用运行验证完成，且发布使用本轮明确授权
- **THEN** 发布到原组件标签与同名文件，索引的下载大小和摘要与公开下载一致，已有安装不被自动升级

#### Scenario: 已授权资产更新需要回滚

- **WHEN** 新资产未通过发布后字节核验或发现功能回归
- **THEN** 使用预先保留的原归档和索引恢复对应项，不删除历史编译证据和用户容器
