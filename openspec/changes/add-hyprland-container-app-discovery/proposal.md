# Hyprland 容器桌面会话与应用发现（用户已确认实施）

## 目标与用户最新意图
用户要求自动发现 Hyprland 容器可用程序，并进一步提出采用类似 XFCE 的分工：Native 仅提供合成器，桌面其余部分交给容器。以该架构替代上一版“宿主读取容器目录并发布菜单镜像”的方案；应用自动发现仍是本轮验收目标。

当前 XFCE 实际为宿主 X server 加容器 xfce4-session；Hyprland 同时承担 Wayland 显示服务器和窗口合成职责，因此宿主保留 Hyprland 及 Android 必要桥接，Ubuntu 容器承载完整客户端桌面会话。

## 用户可见行为
PRoot 的面板、启动器、通知、壁纸客户端、终端、文件管理、软件中心及其 GTK/图标/字体主题均在当前容器运行和管理。应用菜单直接从容器的标准桌面文件发现程序，安装和卸载后自动刷新；应用直接由容器会话启动。m3ww 与 Classic 为容器桌面外观预设，不再要求宿主分别维护应用名单或目录镜像。

容器预设与宿主合成器版本独立安装和选择；仅依赖所用 Wayland/IPC 协议和配置接口能力，不以固定的一对一版本组合限制普通主题资源。Hyprland 自身配置仍由宿主合成器读取，涉及配置接口的部分须验证兼容，不能承诺任意版本、任意网上 dotfiles 无需适配即可使用。

## 范围与边界
只改 Hyprland PRoot 路径；纯 Native 和其他桌面保留现有行为。宿主保留合成器、Android 显示/输入、音频与 USB 桥接、会话生命周期及就绪状态管理；应用 UI 和用户配置归容器。必要窗口操作通过共享 Hyprland IPC，App 快捷操作经单一容器路由，不把宿主应用混入容器菜单。

保留现有用户配置和容器数据。安装、保存、恢复时准备固定配置与依赖；升级已有桌面须先执行一次安装/更新以补齐容器组件，再显式保存后重启，不在普通启动补包或覆盖配置。终端类应用、原生 Wayland 应用和已有 Xwayland 路径分开验收；不因搬迁面板就承诺所有 X11 程序兼容。

## 非目标
不迁移纯 Native 桌面，不改 XFCE/GNOME/Plasma，不重编 Android 合成器，不新增 Snap/Flatpak 支持，不枚举全部 PATH 命令，不声称 PRoot 为安全边界，不无条件兼容任意 Hyprland 配置。未获得外部组件发布、Git 发布、部署或归档授权。

## 风险与回滚
Ubuntu 需要 glibc 版桌面组件，Termux Bionic 二进制不能直接复制。首先验证两种外观所需组件、Wayland layer-shell 和 IPC；若缺组件，记录准确缺口，不偷偷换成另一种外观。保护用户 dotfiles，不自动卸载宿主旧软件包。失败不切回宿主桌面伪装成功。回滚代码后显式重新保存并重启，原宿主配置与用户容器数据保留。
