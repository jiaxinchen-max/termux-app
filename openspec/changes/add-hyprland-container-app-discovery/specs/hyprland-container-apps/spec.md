## ADDED Requirements

### Requirement: 容器承载桌面会话
Hyprland PRoot SHALL 由宿主提供合成器与 Android 必要桥接，容器承载面板、启动器、通知、壁纸客户端、终端、文件管理、软件中心和客户端主题；桌面 UI SHALL 以 termux 用户运行。

#### Scenario: 启动两种外观
- **WHEN** 用户启动已完成准备的 m3ww 或 Classic PRoot 桌面
- **THEN** 客户端桌面组件运行于当前容器，连接当前宿主合成器，不能用宿主面板代替容器会话宣称成功

#### Scenario: 依赖不适用
- **WHEN** 缺少所选外观所需的 Ubuntu 可执行组件或协议能力
- **THEN** 准备明确失败并指出缺口，不复用 Bionic 程序、不静默更换外观、不在普通启动补包

### Requirement: 容器内标准应用发现
应用菜单 SHALL 在容器内直接发现和启动当前用户可见程序，支持标准 XDG 桌面目录、桌面 ID 覆盖、隐藏和显示规则、本地化及可执行性检查，不维护宿主应用目录镜像。

#### Scenario: 安装、卸载及隐藏
- **WHEN** 正常运行中安装带可用桌面入口的程序，或移除、隐藏、使其执行目标失效
- **THEN** 十秒内反映到容器菜单，新打开的启动器显示最新有效应用，不需修改 App 代码、保存设置或重启

#### Scenario: 入口语义
- **WHEN** 应用有带引号参数、Exec 字段码、Path、Terminal=true 或 D-Bus 激活信息
- **THEN** 由容器标准机制正确处理，使用容器终端和总线，不把原始 Exec 拼成宿主命令

#### Scenario: 同名、覆盖和坏入口
- **WHEN** 有同名不同 ID、用户覆盖或损坏桌面文件
- **THEN** 按桌面 ID 保留有效条目和覆盖语义，单个坏文件不阻断其余应用，发现不执行目标

### Requirement: 外观预设与合成器独立
PRoot 的容器外观预设 SHALL 与宿主合成器分开管理，普通主题资源不得仅因合成器版本不同而被强制拒绝；涉及配置和 IPC 的部分 SHALL 依据实际接口能力验证。

#### Scenario: 更换容器外观
- **WHEN** 用户安装或更换已满足依赖和接口要求的容器外观
- **THEN** 应用目录仍由容器自身管理，不要求增加固定应用名单或重装未变化的合成器

#### Scenario: 配置接口不兼容
- **WHEN** 外观预设要求的配置语法或 IPC 接口不被当前合成器支持
- **THEN** 明确报告不兼容，不自动改写任意用户配置，不宣称所有版本通用

### Requirement: 单一会话与宿主桥接
所有容器桌面 UI 和应用 SHALL 共享当前容器 session bus，使用独立 guest system bus；保留当前渲染、音频、USB 与 Android 桥接，不使用宿主总线或 root 桌面。

#### Scenario: 启动应用及窗口操作
- **WHEN** 用户从容器菜单、面板或已适配的合成器快捷键启动应用、切换工作区或操作窗口
- **THEN** 应用运行于当前容器，窗口命令只作用于当前合成器，桌面会话身份贯穿全部过程

#### Scenario: 关键服务故障或停止
- **WHEN** 必要容器组件退出或用户停止桌面
- **THEN** 撤销就绪，按 USB、会话服务、合成器的依赖次序停止当前会话，只清理所属进程，其他桌面不受影响

### Requirement: 兼容与交付
实现 SHALL 保留纯 Native 和其他桌面行为及用户配置；固定准备在安装、保存和恢复完成，普通运行只启动服务与产生动态状态。

#### Scenario: 升级或回滚
- **WHEN** 用户更新后显式保存桌面设置，或显式回滚代码并重新保存
- **THEN** 按新选定架构启动，保留用户 dotfiles、主题和容器数据，不在普通启动迁移、覆盖或自动兜底

#### Scenario: APK 交付
- **WHEN** 后续本地 arm64 构建完成
- **THEN** 保持文件名 termux-app_apt-android-7-debug_arm64-v8a.apk，记录签名、源资产和验证范围，真实 Android 图形及输入需设备验收
