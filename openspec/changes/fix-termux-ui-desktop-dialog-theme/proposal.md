# 修复模块内桌面选择弹窗的主题适配

## 目标和已确认范围

上一轮深浅色审计确认：桌面创建和桌面编辑中的选择框直接使用 MaterialAlertDialogBuilder，浅色模式保留黑色遮罩，绕过统一窗口背景与边线。用户本轮要求“先修复termux-ui模块内部的适配问题，剩下的以后再处理”，明确授权实施审计中模块内部的修复建议。

本变更将上述两处选择弹窗接入已有 FrostedDialogBuilder。实际页面验证进一步确认桌面编辑面板自身在浅色下仍保留黑色 dim，因此同属模块内部的父面板也接入现有 FrostedWindow 遮罩处理。浅色模式采用统一暖色遮罩，深色模式保留现有统一暗色处理；保持分辨率、刷新率、渲染器候选、选中值、回调与保存行为。

## 非目标

termux-x11 的控制器配置、控件编辑及外接手柄映射页面暂不处理。此次不调整整体调色板，不更改运行时主题、Wine、资产、路径、网络或权限，不加入迁移和兼容逻辑。

## 文档、风险与审批

无 HTTP 契约变化，api_docs 为 N/A。用户可见的弹窗表现变化，product_docs 为 Required，计划在验收后维护 docs/product/ui-appearance.md，一致性 Pending。仓库没有该产品基线及 Harness 引导、严格脚本和 OpenSpec CLI，记录实际本地验证，不声明严格门禁通过。

用户已确认修复建议和模块边界，本规划记录已授权的两处替换，不新增待决设计。回滚仅恢复两处原有 builder，不涉及用户数据。Git、部署和设备操作不包含在授权中。
