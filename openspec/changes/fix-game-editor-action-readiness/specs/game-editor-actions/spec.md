# 游戏与容器操作

## ADDED Requirements

### Requirement: Launch 只能在当前配置保存并准备成功后使用
系统 MUST 在新导入未 Save、保存中、准备中、失败、取消、就绪信息读取失败或有未保存配置修改时将 Launch 置灰，并在点击处理阻止启动。共享运行环境存在和目录可访问 MUST NOT 单独放行。

#### Scenario: 两后端首次导入
- **WHEN** 用户导入 Native 或 PRoot 游戏，尚未 Save
- **THEN** Launch 置灰且直接触发点击也不能启动
- **AND** 编辑、资源管理、Save 和删除仍可操作

#### Scenario: 准备不成功或配置有修改
- **WHEN** 当前配置准备未终结、失败、取消、必要环境信息缺失或出现未保存修改
- **THEN** Launch 不能执行，历史成功不能覆盖当前失败

#### Scenario: 正常成功
- **WHEN** 当前配置已经保存并准备成功，环境完整、无待保存修改且游戏目录可访问
- **THEN** Launch 可以启用

### Requirement: 编辑和删除不按任务状态拒绝
系统 MUST 对 Native 与 PRoot 的游戏和桌面容器统一采用强制终止后操作；不得因运行中、准备中、失败、取消或停止中的任务状态隐藏或禁用编辑删除入口，也不得要求用户先手动停止。

#### Scenario: 编辑运行或准备中的游戏
- **WHEN** 用户进入游戏详情或运行配置编辑
- **THEN** 先强制终止该游戏及共享同一前缀的关联运行和准备工作，再加载编辑内容
- **AND** 用户可以修改、保存或删除

#### Scenario: 编辑桌面容器
- **WHEN** 用户打开任意 Native 或 PRoot 桌面容器设置，或保存修改
- **THEN** 先强制终止关联工作，允许编辑和保存，不因停止中状态拒绝

#### Scenario: 删除运行中的对象
- **WHEN** 用户确认删除游戏或桌面容器
- **THEN** 先取消关联任务和强杀关联进程树，再执行既定删除范围
- **AND** 原始游戏目录和共享基础环境保持原删除边界

#### Scenario: 强杀失败
- **WHEN** 无法完成关联进程或工作线程的强制终止
- **THEN** 显示操作失败，不伪装成功继续删除

### Requirement: 强杀后的任务不得重新启动
系统 MUST 取消已经提交但尚未落盘或尚未创建进程的关联命令，且后台服务不能通过旧快照、迟到事件或重协调重新启动已取消任务。

#### Scenario: 宿主尚未执行启动命令
- **WHEN** 用户强杀时关联启动或准备 Intent 尚未实际创建进程
- **THEN** 创建边界拦截该命令，不在编辑或删除后重新启动

#### Scenario: 无关对象隔离
- **WHEN** 强杀某对象的任务和进程
- **THEN** 排除 Android 主进程、无关 UID 和无关容器；共享同一 Native 前缀的关联游戏统一停止

### Requirement: 生命周期遵守 Launch 门禁
系统 MUST 在页面恢复、准备结果变更和旋转重绑定时保持 Launch 状态正确，忽略过期回调；事件处理与可见按钮使用一致规则。

#### Scenario: 旋转未准备好的编辑页
- **WHEN** 用户旋转屏幕或重新进入编辑页
- **THEN** Launch 不会短暂误启用，编辑和删除仍可操作
