# 游戏操作门禁与编辑删除强杀

## 问题与目标
导入游戏已经持久化配置，但首次 Save 后才提交运行准备；原编辑页仅检查游戏目录可访问就启用 Launch，导致未 Save 或准备失败仍能启动。用户进一步明确：PRoot/Native 均适用，编辑和删除不能按任何运行、准备任务状态拒绝，统一先强杀；删除在强杀后执行。

目标：Launch 在未保存、准备中、准备失败/取消、当前环境不完整或有未保存配置时置灰，并拦截直接点击；当前配置保存且准备成功才启用。编辑、资源管理和删除保持可进入。进入游戏或桌面容器编辑前强制终止关联运行与准备工作；删除时先强杀后删除，不隐藏运行中的删除入口，不要求用户手动停止。

## 范围
覆盖游戏详情、独立/嵌入运行配置、游戏卸载、桌面 Native/PRoot 设置与删除、宿主按私有路径强杀进程树、准备/启动服务取消边界，以及相关归档工作线程取消。取消尚未落盘或尚未实际启动的命令，防止后台重新拉起。共享同一 Native 前缀的关联游戏一起停止；不杀 Android 主进程和无关容器。

## 非目标与兼容性
不切换后端、不改变 Wine 版本选择、不增加 wineboot、prefix 重建或回退；不做历史数据迁移。不恢复已删除的摘要/签名校验，不修改镜像和组件资产。无 HTTP 契约变化。原始游戏目录及共享基础运行环境保持原卸载边界。实际设备由用户手动验证。

## 风险、验证与回滚
强杀会中断对象的当前工作，这是用户明确要求的行为。进程终止失败明确报错，不伪装为成功后继续删除。新逻辑只读检查就绪信息；运行任务的强杀按关联私有路径匹配同 UID 进程并终止子树。测试覆盖两后端任务状态、未保存 Launch、事件拦截、旋转、先取消/强杀后删除、待启动任务取消、进程隔离和容器状态。回滚仅撤销本变更代码及测试，不重置既有未提交修改，不清理设备。
