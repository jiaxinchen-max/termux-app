# Design

## Context

现状证据见artifacts/proot-minimization/app-acceptance/result.json：正式共享根已验证五批精简，1401 ELF、1594保护路径、两份前缀PE32/PE64/中文/软件图形音频通过。完整基础重建1919.276秒，前缀准备29.284/31.183秒。完整候选tar.zst为322987180字节，但它是实验候选归档且规范化mtime，不具备正式发布凭据，不能未经审核直接作生产下载源。

现有v11将Hangover deb当基础组件，统一解压器支持tar/xz/gzip且拒绝逃逸链接；不支持zstd。PRoot根含客体绝对链接和.l2s实体，不能放宽全部组件的通用解压规则。宿主PRoot、Python、dbus/PulseAudio和X11仍在Termux侧提供。

## Goals / Non-Goals

目标是新安装/显式重建走完整预装镜像，下载后一次解压、校验、同文件系统原子发布；不再出现未裁剪Debian树和deb安装中间数据。保持唯一共享基础根和独立前缀，源缓存不保留第二份展开RootFS。

不做进一步裁剪、Wine重编译、旧用户数据迁移、硬件能力扩展、完整游戏兼容承诺或APK改名。失败不自动回退apt；恢复旧版本采用原APK/原镜像及显式重建，活动C盘不覆写。

## Decisions

### 1. 独立镜像载荷及两级身份

新增不可变镜像组件身份，运行选择值仍为rootfs_hangover_11.16。新配方版本与镜像摘要、打包清单、客户端安装工具一起计算安装身份；Wine来源ed206c70ca889b1bbbcedaa93d4018d315b3512a861dec551da8093f9a1807c1独立记录，禁止将镜像摘要冒充Wine来源摘要。前缀bundle保留manifest/delta/runtimeFiles字节，只有经逐来源验证后重绑基础配方。所有setup/启动/复用消费者一致更新。历史任务允许明确拒绝并提示重建，不添加旧安装流程兼容回退。

新安装/重建只准备镜像载荷，不因Hangover运行选择值再下载旧deb组件；备用Wine、Box64、DXVK仍按选择下载。载荷为raw压缩文件进入组件框架的SHA验证和不可变缓存，不先通用展开再复制。发布目录与下载缓存仅有压缩副本和一份展开共享根。

### 2. 正式打包输入和凭据

从无人运行的已发布精简根导出，保留文件模式、客体链接、.l2s实体与必要空挂载目录；拒绝包含游戏前缀/导入文件/用户home/测试探针/缓存/凭据/非空游戏绑定目录。机器ID、主机标识、解析器等逐项审核，按明确允许清单清理非运行身份，不整目录盲删。保留许可证、dpkg来源记录、locale/fontconfig和前缀来源文件。

采用tar.zst以沿用实测压缩和快速解压；宿主检查/安装zstd解码工具，属于Termux依赖，不引入客体apt。包外可信目录固定URL、字节数、SHA；包内版本化清单记录成员大小/类型/模式/摘要/链接及来源和裁剪策略。镜像清单身份与客户端配方身份分开，防止归档摘要自引用；客户端不伪造旧裁剪receipt，验证镜像后写新的安装receipt。约308MiB只是已有候选参考，正式包以产出实测为准。

### 3. 专用安全还原和发布

宿主专用还原器流式解码到固定任务私有scratch：拒绝绝对成员路径、..、重复成员、设备/FIFO、越界硬链接、通过已建立符号链接写文件、保留控制文件覆盖、超出数量/展开字节预算、截断或额外不合法输入。客体绝对符号链接只按客体语义校验闭包，建立链接不读写宿主目标；.l2s保持相对可迁址。取消须杀解码子进程并清理本任务暂存，错误有稳定状态和日志；中断只回收有所有权标记的scratch。未知旧目录不删除。

正式发布前核对镜像版本/来源/每成员及前缀公共来源、运行入口、依赖和客体链接、UTF-8/GBK/fontconfig；全量哈希尽量合并在流式解压中，避免多轮重复扫描。发布复用现有串行任务gate和previous回滚。新根与最终路径核验成功后再切换安装receipt并清理旧根；失败恢复旧根与旧receipt，不动任何游戏C盘。

### 4. 模块、进度和存储

Activity沿用核心组件安装/重建入口，显示下载、解压、校验、就绪，不新增包管理操作；ForegroundService拥有持久状态、冻结输入和并发gate。codec传递受控镜像路径和身份，shell只准备宿主和还原镜像，不再进入客体setup-container.sh。新配方无需该脚本作为安装消费者；保留离线镜像生产工具和历史证据。

X11、输入和音频启动边界不变。每游戏继续从APK约3MiB差量模板加共享运行来源还原约824MiB独立可写前缀。空间预算计入压缩缓存、新展开根、当前旧根（替换期间）、所选前缀及安全余量，防溢出；不得沿用旧4.84GiB构建预算或宣称下载字节就是展开空间。

## Risks / Trade-offs

- 客体链接导致宿主逃逸 → 专用还原器、延后链接写入或等价防护、恶意归档故障测试，不放宽通用组件规则。
- 新身份使共享根与前缀错绑 → 分离镜像/Wine/配方身份，覆盖所有消费者、源守卫逐字节测试。
- 镜像携带机器/用户资料 → 打包白名单、全成员报告、干净输入与独立复核。
- 解压或取消失败 → 私有暂存、自然等待终态、旧根和receipt保留、真实中断/空间不足测试。
- 首次宿主依赖仍联网 → 说明Termux依赖属于必要宿主，不承诺完全离线；客体包仓库不可访问时安装仍应成功。

## Migration Plan

规划确认后准备正式制品和还原器，完成故障/消费者测试再发布新不可变镜像资产；发布URL/大小/SHA机器核验后启用目录。Git和外部发布分别需明确授权，不沿用历史PAT推送指令；发布审批前先准备精确文件、清单及命令。测试端可用已校验本地缓存验证，不将临时URL作为正式分发。编译固定原名普通APK供用户手动安装，实际App验证冷安装、缓存复用、显式重建及两份全新前缀；同时采集耗时、下载字节和空间峰值。最终接受后完成产品一致性，未经授权不归档。

高风险范围为组件激活/下载目录、安装Service/spec codec、配方及前缀绑定、setup/launch/恢复脚本。权威policy id和Harness文件缺失，记Unavailable；历史参考runtime-script-critical，不冒充现行策略。影响、回滚及验证按上述记录，具体规划和此范围须确认后修改业务代码。
