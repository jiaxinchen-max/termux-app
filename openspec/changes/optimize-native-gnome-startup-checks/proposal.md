# 原生 Ubuntu GNOME 静态检查仅在安装初始化执行

用户在诊断后要求优化，并进一步明确“启动阶段做检查实在多余，有问题就该退出”。最终确认范围为：日常启动不做主题/文件完整性校验、初始化缓存比对或运行依赖预探测；这些检查仅在安装初始化与显式诊断时执行。运行时真实错误和进程退出继续作为失败处理。

当前启动入口及 Python 启动器各执行一次完整主题校验，并串行运行六项依赖探测。独立复测曾分别耗时 152 秒和 18 秒，实际成功启动也曾仅需 7.8 秒，不能将复测值等同于每次启动耗时。

本轮移除原生 Ubuntu GNOME 启动前的上述静态检查；保留参数约束与实际会话进程/显示/Shell/扩展就绪失败处理。安装必须完成主题校验与依赖探测才写入成功标记。组件更新后不会在启动时自动扫描；发现实际运行错误应退出并提供日志，通过重装或显式诊断检查。PRoot 不在本轮范围，D-Bus 查询单次超时策略保持原状。
