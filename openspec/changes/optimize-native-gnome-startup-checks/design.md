# 设计

原生 Ubuntu GNOME 的主启动脚本不再调用 desktop_native_ubuntu.py 校验。共享启动器仍从相邻资产加载配置常量（模式和扩展列表），但原生分支不再调用 validate/runtime_probe 或缓存检查；PRoot 原有行为保持。

静态完整性与依赖预探测全部保留在安装函数中：安装开始撤销 .installed 标记，验证归档与解包路径，提取后执行完整 validate 和 runtime_probe，全部成功后才写入原有纯 SHA 安装标记。错误不得留下安装成功标记。CLI 不带 --install 是显式诊断操作，执行完整校验及依赖探测，不参与日常启动。无需增加缓存、文件指纹、版本戳或初始化锁。

启动参数约束、渲染连接、当前进程存活和就绪检测属于本次会话运行结果，继续保留。启动失败按既有错误路径结束，不吞异常、不自动回退渲染模式。本轮不改 D-Bus 单次超时策略。

验证安装成功/归档错误/主题损坏/依赖错误的真实模块行为；验证原生入口和启动器无静态检查调用，保留 PRoot 调用边界；CLI 显式诊断仍能检查。设备使用隔离资产启动测试，不替换已安装 APK；记录完整会话是否通过，不能把模块测试视为 APK 回归。

风险：安装后非关键图标被改坏时，启动不再通过预扫描发现；按用户要求由实际运行结果暴露，通过重装或显式诊断排查。回滚三个脚本即可恢复原启动预检查。本轮不修改高风险权限、网络、证书、包配方或原生后端。Harness 与 OpenSpec CLI 缺失时记录 Unavailable，不伪造通过。
