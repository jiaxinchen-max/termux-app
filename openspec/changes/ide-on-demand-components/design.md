# 设计（已批准）

## 构建和分发
复用现有组件目录和下载/校验/原子安装事务。tooling 独立构建生成 JAR、许可证、源码版本和组件清单。主 APK 保留固定的组件 ID、版本、协议、HTTPS 地址、字节数和非空 SHA256，以及许可文本，不再嵌入重型 JAR。普通 assembleDebug 不执行远端上传，保留标准 APK 名称和类型。组件发布目标为 jiaxinchen-max/termux-app-packages，具体资产地址需上传确认存在后才能固定到宿主；不引用不存在的资产。

## 使用流程
只有首次执行项目同步等依赖 tooling 的动作才下载；打开 IDE、编辑文件不下载。前台任务显示准备组件和进度，允许取消、失败后重试。复用已通过完整内容校验的本地组件，匹配版本时断网可用。禁止因进入 IDE、旋转屏幕或重复同步而重复下载。

## 信任和兼容
外部存储下载缓存不能直接执行。执行前检查固定大小、SHA256、组件及协议版本，安装到应用私有目录，再用原有 Termux native Java 启动。不能继承允许空 SHA256 的旧组件规则。组件包内自报校验值不能覆盖宿主固定值。协议不匹配应明确报错；取消或中断不能激活半成品，也不能破坏上一个完整版本。宿主升级只使用与本身协议匹配的版本，不静默运行旧版本。

## 集成边界
现有 enqueueRuntimeDependency 与 Wine/运行环境安装门禁耦合，IDE 不能直接借用 Wine 父任务身份。应核对通用 ComponentTasks 下载入口的安装门禁，再增加最小 IDE 前台任务适配。任务取消只取消本次持有的下载，不能中止其他功能共享的下载。许可证继续随 APK 可离线查看。

## 影响与回滚
受影响构建路径为 termux-ui/build.gradle 与独立 tooling 构建脚本；不改变宿主 minSdk、签名、ABI 或命名。回滚可恢复原 assets 打包与解包路径；失败不得改写用户项目或原生运行环境。用户已确认本设计及构建影响。

## 实施决策

使用已有 ComponentDownloader 和文件任务仓库，IDE 前台任务是唯一下载执行者，避免重复引入第二个前台组件任务及 Wine 门禁。任务记录/下载缓存位于应用私有 ide-components 目录；稳定的摘要任务 ID 支持重试复用。安装使用既有 IdeToolingRuntime 的 AtomicFile 路径，按摘要隔离版本，保留旧完整文件，不使用与 Wine 归档和激活器耦合的 ComponentInstaller。执行前再次验证大小、摘要与 JAR 的 Termux-Tooling-Protocol=1；拷贝时再次计算摘要，提交原子文件前检查取消。主 APK 的 component.properties 固定版本及协议，不接受远端自报的版本覆盖。

组件发布位置为 releases/tag/ide-components，宿主固定 androidide-tooling.jar 的 SHA256。未来替换同名组件必须同步固定宿主清单；旧宿主已安装匹配缓存仍离线可用，旧宿主缺少匹配缓存时不能把新内容当成旧版本运行，须提示更新或恢复匹配资产。
