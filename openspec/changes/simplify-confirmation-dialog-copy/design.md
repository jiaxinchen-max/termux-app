# 设计

## 文案规范
正文只描述用户执行后的结果，优先单句、单段，不使用项目符号、重复的“是否继续”、内部路径和实现术语。删除进程枚举、包管理器步骤、校验流程及缺乏保证的耗时估计。覆盖对象、删除范围、不可撤销性、未保存数据丢失和确实限制操作的兼容条件需保留。已简短准确的文案保持原状。

## 实施
以 copy-preview.md 为具体中文评审依据，默认英文同步含义。仅修改现有字符串和必要的正文拼接；桌面归档导入去掉当前正文附加的绝对路径，不修改来源选择流程。复用原资源 ID、格式占位符和所有按钮、选项及执行回调。保留游戏和桌面删除中的选项来表达实际删除范围；不同流程不套用会造成错误承诺的统一文案。

## 核对与验证
逐一关联确认入口与真实执行分支，确认实际覆盖/保留范围后落实文案；不沿用过时校验或初始化保证。核对中英文占位符、XML 有效性和资源引用，执行 Android 资源编译；不为文案编写镜像测试，不进行模拟器操作。用户按既有要求手动验收。如需 APK，保持原有 arm64 普通 debug 命名和 testOnly=false。

## 回滚与约束
回滚只还原本次文案及正文拼接，不触及其他未提交修改。不引入兼容、迁移、回退、校验或执行行为变化。

## 环境限制
仓库缺失 Harness 引导文件、strict verifier、OpenSpec CLI、基线 specs 与 docs/product 索引。以本地规划与直接源代码核对记录证据，不宣称严格门禁通过。
