# 设计：固定卡片几何边界

## 根因与现状
`item_local_game.xml` 根节点和纵向正文使用内容高度。Wine 行 `maxLines=2` 仅限制上限，不为短文本预留同等高度；两种 Wine 名称因换行得到不同测量高度。Activity 为所有游戏指定 `WRAP_CONTENT`，导入项另用 `GridLayout.FILL`，进一步造成不一致。

## 布局调整
新增游戏库专用高度资源 180dp，保持现有封面 56dp 和网格卡宽规则，避免改变桌面管理已经确认的 128×160dp 设计。网格游戏和导入项的 XML 及实际 GridLayout 参数同时使用相同高度，按行顶部对齐，不依赖同行内容撑高。

卡片内部占满根节点。固定封面和底部操作，正文放在受约束的剩余区域。名称／Wine／状态采用单行尾部省略，可执行文件固定两行并省略；不使用字符串 substring 修改保存值或切断中文。长字段、缺失字段、错误状态或最近游玩状态均不得改变卡高。大字体下保持操作区域，文本在可用空间内限制行数或缩放，不能以挤出按钮维持正文高度。

封面 ImageView 保持固定边界，使用 `fitCenter` 等比例完整显示；默认占位图和宽图、长图、方图遵循同样边界。沿用异步加载与过期 generation 检查，不新增图片原尺寸布局或无限制大图解码。

列表维持现有全宽行布局，只约束 Wine 为单行并对齐图片缩放策略；不将列表强制为网格卡片尺寸。Native／PRoot 复用同一路径，不按后端写分支。

## 验证与风险
针对实际 Android 测量核对同排短／长 Wine、中文长标题、长 EXE、错误状态、默认占位图及不同比例位图，在横竖屏、浅深主题和放大字体下尺寸一致，详情／更多区域可用；异步替换封面前后尺寸相同。复用现有列数和卡宽单元测试，确认导入项位置与布局切换不退化。保留完整文本与现有详情能力，避免视觉省略影响实际 Wine 身份。

仓库缺 Harness bootstrap、strict 脚本、OpenSpec CLI 和产品基线，如实记录工具缺口，不能把源码检查称为设备视觉验收。回滚仅撤销本变更的布局、摆放与尺寸资源，不涉及游戏配置或容器数据。没有发现额外受保护路径规则；实施前再次检查适用指令。

## Desktop 扩展设计及已有规范关系
沿用 fix-desktop-manager-fixed-card-size 的管理网格128×160dp与52dp封面。检查长标题与模式角标、进度条的分区；正文和状态按可用高度受限并省略，底部按钮保持48dp且不按字体基线互相推移。列表操作列采用有界宽度，主按钮单行省略，避免长操作标签占满整行；正文保持可用宽度。新增／导入标签限制行数并尾部省略。
创建页沿用 unify-desktop-types-cover-grid 的字体自适应宽度及允许增高规则，不将其强制改成管理网格高度。标题固定两行、超长尾部省略，同字体下高度一致；完整名称仍在TextView和现有contentDescription，不修改桌面类型值。此处根据用户最新同类修复要求，细化历史“完整名称”为数据和无障碍描述完整、封面展示有界。状态区与选择标记预留独立空间。图片显式fitCenter，不因原图尺寸改变卡片布局。
验证需先用真实资源复现，再覆盖字体1/1.3/2倍、浅深主题、中英文长名称、安装状态、长操作标签及三种封面比例；管理页、列表及创建页分别遵守各自尺寸约定。
