# 修复 Wine 与 Desktop 卡片展示边界

## 问题
用户截图中同一行两张 PRoot 游戏卡片高度不同。`item_local_game.xml` 的卡片和正文均为 `wrap_content`；Wine 文本仅设最多两行，长名称换行后增加实际高度。`LocalGamesActivity.applyGameCardLayout` 同样使用 `WRAP_CONTENT`，仅导入卡片填充所在行，因此卡片与底部操作不能对齐。

封面当前有固定高度，但使用 `centerCrop`；本次改为固定区域内等比例完整缩放，异步加载不得改变几何尺寸。

## 拟议修复
- Native／PRoot 游戏网格共用固定卡高 180dp、封面高 56dp，导入卡片使用同一高度。保留现有按窗口宽度计算列数和卡宽的规则。
- 名称、Wine、权限状态单行尾部省略；可执行文件保留固定两行并尾部省略。完整数据保持原值，可在现有详情／运行配置中查看。
- 固定底部详情和更多操作区域；正文只能使用剩余空间，不得撑大卡片或推移按钮。
- 卡片和列表封面等比例缩放、不拉伸、不裁掉图片，列表 Wine 信息同样单行省略。
- 保留启动、安装中动画、详情、更多菜单、后端筛选和深浅主题；不修改容器或 Wine 运行逻辑。

## 范围及文档
仅涉及游戏库布局、摆放参数、尺寸资源和针对性验证。无 HTTP 合约变化，`api_docs=N/A`。影响可见展示，`product_docs=Required`，接受后更新 `docs/product/local-games.md`，当前一致性为 Pending。

用户已明确要求修复长文字和图片影响尺寸的问题。用户于 2026-11-18 明确“批准”本方案，Stage 1/2 已确认，授权本范围实施；不自动提交、推送、安装 APK 或归档。
