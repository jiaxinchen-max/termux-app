# 桌面重新安装

## ADDED Requirements

### Requirement: 统一而明确的重新安装入口
所有受支持 Native 和 PRoot 桌面更多菜单 MUST 显示“重新安装”，不得因已安装状态不同而不一致；退役 GNOME SHALL 不提供。有桌面会话时 MUST 保持可用，确认后 MUST 先杀死相关进程并确认退出，再安装。活动安装及归档冲突 MUST 由后端再次保护。

#### Scenario: 空闲桌面重装
- **WHEN** 用户在受支持桌面菜单选择重新安装并确认
- **THEN** 提交该 ID 的显式重装任务并显示其安装控制台；取消确认不提交。

#### Scenario: 确认期间状态变更
- **WHEN** 菜单打开后出现桌面会话或设置变化
- **THEN** 后端重新读取当前库存，先保护所有桌面的活动安装，再结束受管理桌面进程树并确认退出，之后才提交重装；停止失败保留原规格、不提交安装。同一桌面已有安装时复用任务，不重复安装；其他活动安装和归档冲突阻止操作。

### Requirement: 重装实际执行且保留用户数据
重装 MUST 为安装任务设置独立重装标记，相关软件包 MUST 以重新安装模式执行。Hyprland 已验证运行时 MUST 在显式请求时重新部署；下载归档 MUST 仍经过原校验及原子替换。普通安装和本地准备 SHALL 保留已有行为。MUST 保留桌面 ID、设置、现有容器及用户文件，不删除容器。确认文案 MUST 说明重装范围与文件保留。

#### Scenario: 已安装组件和失败传播
- **WHEN** 组件已安装，用户确认重装
- **THEN** 仍调用重新安装分支，重新准备会话；任何失败由既有安装终端返回真实失败，不写成功标记。
