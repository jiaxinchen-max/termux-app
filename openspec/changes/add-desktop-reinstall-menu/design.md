# 设计

DesktopActivity 为所有受支持 Native/PRoot 卡片加入“重新安装”，会话活动时保持可用，仅安装或归档冲突时保护；退役 GNOME 不提供此项。点击先确认，取消无提交；确认调用 DesktopTasks.reinstall 并连接既有真实安装终端。确认后在操作锁内重新读取当前库存，验证桌面支持状态，并先检查所有桌面无活动安装、归档；随后逐一复用 forceStop 杀死受管理桌面相关进程树并等待退出，全部成功后才部署规格和提交安装。不能因 starting/running/stopping 拒绝重装；任一停止失败不写重装规格、不提交。停止全部受管理桌面以保护共用宿主软件包；确认文案明确此影响。重复提交复用同一桌面的活动安装。

重新安装沿用原有 DesktopTasks.install 调度与结果记录，但专用入口将 DESKTOP_REINSTALL=1 写入新生成的安装规格。普通安装、保存准备、USB 与主题切换不带此标记。shell 校验标记仅为 0/1，且不能与准备、USB、主题切换或宿主预置操作混用。Native 已有 apt --reinstall；PRoot 桌面与 Hyprland 宿主依赖增加显式 --reinstall。Hyprland 的已验证运行时检查不能跳过用户明确要求的重装，Python 安装器增加 --reinstall 以原子重装经过校验的归档；默认调用仍保留幂等优化。主题和 EWW 若验证完整可复用，不强制下载或重新编译。

通过实际 Activity 菜单点击/取消/确认、忙碌条件及后端二次检查测试，验证任务规格和控制台；通过真实 shell 分支与 Hyprland 原子安装器红绿测试验证不是空操作。设备 120.24.191.156:8057 已连接，当前 APK 哈希与上一 Native 入口修复一致。先验证现有版本 UI；新的 APK 设备覆盖安装仍需明确的部署命令授权，不擅自安装或执行设备桌面重装。可交付已构建、原名、原签名且完整下载校验的 APK，用户自行安装后再验证新菜单。
