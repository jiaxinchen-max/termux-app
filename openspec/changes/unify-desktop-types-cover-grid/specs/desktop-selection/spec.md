# 桌面类型与创建选择增量规范

## MODIFIED Requirements

### Requirement: 两种模式使用统一四类型
Native 与 PRoot 必须仅支持 XFCE、Plasma、Ubuntu GNOME、Hyprland 四种桌面。独立 GNOME 不得被创建、保存、安装或启动；Ubuntu GNOME 仍须保留自身原生显示链路与共享 GNOME 组件。本要求取代历史 add-native-ubuntu-gnome 中“保留普通 GNOME 卡片”及 unify-proot-ubuntu-2604-retire-gnome 中“保留 Native GNOME”的范围，历史记录不作伪造或删除。

#### Scenario: 任一模式进入创建页
- 当用户进入 Native 或 PRoot 创建页
- 则恰好显示 XFCE、Plasma、Ubuntu GNOME、Hyprland 四个卡位，按此顺序排列，不显示独立 GNOME。

#### Scenario: 绕过 UI 调用已废弃类型
- 当调用方以 Native 或 PRoot 模式尝试创建、保存、安装或启动独立 GNOME
- 则明确拒绝，不执行包安装或会话启动，不隐式转为 Ubuntu GNOME。

### Requirement: 紧凑封面卡片自适应排列
四类桌面必须按实际可用宽度自动排列，不固定行列数；内容尺寸参考 Wine 程序卡片，避免为填满整行放大卡片。每项提供各自本地轻量封面和完整名称，支持点选卡片及可见单选状态。窄屏、分屏、大字体和横屏不应造成横向溢出、卡片重叠或名称与状态遮挡，允许页面纵向滚动。本要求取代本变更早期固定两行两列的规划。

#### Scenario: 可用宽度变化
- 当用户旋转屏幕或调整窗口宽度时，列数根据紧凑卡片所需空间自动调整，四类类型及顺序不变。
- 当一行剩余空间不足容纳一张卡片时，换行，不把已显示卡片拉宽填满整行。
- 当窗口过窄或字体变大时，减少列数或增高卡片，确保名称和主操作可读可用。

卡片必须采用紧凑的小横幅封面、较小的间距和内边距，不随卡宽把封面放大成主要内容。启动按钮采用较小的可见背景并保留足够触控范围；大字体下允许扩展，不能用裁切文字换取固定高度。

创建页和桌面网格卡的名称必须叠放在封面左下角，通过底部渐变衬底保证可读性；正文不再重复名称。名称、右上模式角标与底部扫描条不得相互遮挡；长名称或大字体时允许封面增高。

#### Scenario: 选择任一可用卡片
- 当用户点击卡片
- 则只有该卡片显示选中状态，保存的桌面类型与卡片一致，并同步更新适用的渲染、主题和命名字段。

### Requirement: Native 唯一性与固定卡位并存
每类 Native 最多创建一个实例；已创建项仍占原卡位，显示“已创建”且不可重复创建。PRoot 允许同类型多实例。

#### Scenario: 部分或全部 Native 已创建
- 当部分类型已创建
- 则保留全部四卡，默认选择首个仍可创建项。
- 当四类均已创建
- 则保留全部四卡，创建按钮禁用并说明原因，不自动选中不可创建项。

#### Scenario: PRoot 已有同类容器
- 当用户已有相同桌面类型的 PRoot 实例
- 则该类型仍可选择，新实例继续使用原有命名和别名规则。

### Requirement: 数据和启动阶段约束
系统不得因本变更自动删除、迁移或转换用户数据，旧独立 GNOME 记录仍可显式删除。所有持久初始化继续只在保存／安装阶段完成，启动阶段不得新增依赖扫描、修复或重试，失败直接退出。

## ADDED Requirements

### Requirement: 安装期间显示左至右扫描动效
桌面卡片安装期间必须使用从左至右循环的横向光带代替圆环；光带具有高亮前端与渐隐拖尾，颜色随浅深主题适配，保留封面图标、桌面名称和安装状态，不伪造百分比。

#### Scenario: 安装与可见性变化
- 当桌面正在安装且卡片可见时，显示单向左至右的扫描动画。
- 当安装成功、失败或取消，或页面／卡片不可见时，停止扫描动画。
- 当重新显示仍在安装的卡片时，恢复扫描动画。
- 当系统禁用动画时，保留静态安装状态提示，不强制循环动画。

### Requirement: 完整深浅主题适配
四种桌面在 Native／PRoot 的封面卡片、名称、状态、选中态、扫描动画、实体按钮和确认弹窗必须跟随现有应用深浅主题设置，保持文字与按钮可辨。切换主题不得重置实际安装任务或触发新启动。

#### Scenario: 安装或确认期间切换主题
- 当正在安装或显示启动确认框时切换应用主题
- 则适配后的图标、文字、光带和按钮仍清晰，实际任务与待确认意图不因重绘被重复提交。

### Requirement: 实体启动按钮与二次确认
桌面网格卡片必须在左下角显示有明确填充背景的“启动”按钮；运行中可显示“进入”。两种模式及列表布局采用一致的确认规则，卡片正文／封面不得触发启动或进入会话。实际启动／进入前必须显示包含桌面名称和运行模式的确认框，只有确认才可进入会话页。安装中仍提供查看安装日志的操作，不冒充可启动状态。

#### Scenario: 取消与误触
- 当用户点击卡片正文或封面时，不启动桌面、不进入会话页。
- 当用户点击“启动”后取消确认或按返回键时，不进入会话页、不执行启动。

#### Scenario: 确认与重复点击
- 当用户确认启动／进入时，只发出一次进入请求。
- 当用户连续点击按钮时，不叠加确认框或重复启动。
- 当桌面正在启动或停止时，禁用重复操作。
