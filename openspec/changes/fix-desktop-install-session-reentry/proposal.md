# 修复桌面安装会话重入

## 问题与目标
PRoot 桌面正在安装时隐藏控制台，再点卡片会重新进入安装逻辑。当前列表没有安装中状态，DesktopTasks.state 在安装清单不完整时直接返回 NOT_INSTALLED；install 每次生成新任务 ID，不能定位已有控制台。

安装从开始准备到实际完成期间，卡片必须持续展示安装中动画；点击卡片或主按钮只恢复正在执行的安装会话，不再次确认安装、提交安装或打开桌面。隐藏窗口只改变窗口可见性。共享入口同步适用于 native，避免同类重复任务。

## 非目标
不改变底包、桌面依赖或渲染器；不增加启动预检、旧数据迁移、自动失败重试。未安装且没有活动任务时仍允许用户明确发起安装。

## 文档分类
api_docs 为 N/A：只有 Android 本地任务及会话关联，不修改 HTTP。product_docs 为 Required：验收后更新 docs/product/desktops.md 与 docs/product/games.md（当前缺失，待创建），一致性保持 Pending。

## 风险与回滚
需区分服务尚未创建终端、真实安装运行、完成失败和异常丢失，不能永久显示安装中；重复点击需原子去重。按本次差异回滚任务关联、状态与卡片展示，保留其他既有变更。

## 四组合审计后的批准范围

用户已批准 native/proot × Wine/desktop 的审计修复。Wine 保留现有动画与控制台，修复 API 至服务落盘之间的任务 ID 空档，提交前原子持久化 QUEUED 任务，提交失败落 FAILED；服务接收已有同 ID 任务并继续准备。公共安装入口识别 Prefix 父任务，允许其已登记的组件依赖。安装中点击卡片、编辑或删除入口均优先恢复该安装会话，禁止无意中断；已进入编辑页的加载流程也检查并回到安装控制台。桌面安装前记录唯一任务并复用；宿主暴露真实终端创建前的有限期提交状态，过期或丢失须失败并取消迟到任务。所有背景状态仅查询真实任务，无启动安装清单检查。
