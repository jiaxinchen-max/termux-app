# 设计

## 根因与现有边界
DesktopActivity.bindCard 把 NOT_INSTALLED 绑定到 confirmInstall；DesktopTasks.state 先检查 environment.isInstalled，导致安装中状态被未安装覆盖。DesktopSessionState 不包含 INSTALLING。installAndShowConsole 每次调用 install，后者在操作锁内无去重并生成时间戳任务 ID；没有保存桌面到当前任务 ID 的关联。PrefixSetupConsoleDialog 已可按任务 ID 附着真实终端，dismiss 仅停止窗口轮询；宿主通过 TermuxGamesSetupTerminalRegistry 暴露终端。

## 修复方案
1. 建立桌面 ID 与安装任务 ID 的关联，以真实任务生命周期作为安装状态依据，包含终端创建前的提交/准备阶段。Activity 重建和隐藏窗口不丢失关联；服务启动失败、终端结束或任务消失须解除忙碌状态并明确反馈，不靠旧 installing 文本永久占位。
2. 在 DesktopOperationGate 的锁内实现同桌面安装复用：活动任务存在时直接返回已有 ID，不重新部署脚本、不改 spec、不再调用宿主安装入口。避免双击及不同入口竞争。
3. 增加 INSTALLING 状态，列表优先展示活动安装，覆盖尚无完成标记和重装时已有完成标记两种情形。把安装视为占用运行资源，限制安装中启动、再次初始化、修改影响安装的配置和删除等冲突操作；关闭窗口仍可用。
4. 卡片显示持续进度动画与“安装中/查看安装进度”文案。点击卡片或主按钮重新查询当前任务并打开 PrefixSetupConsoleDialog，处理列表快照过期，不重新弹安装确认。结束后取消动画，刷新正常已安装/失败状态；失败仅在用户明确操作后重试。
5. 创建后自动安装、手动重试、设置变更触发初始化统一复用该任务入口。补齐任务关联及生命周期的聚焦测试。

## 模块边界
Activity 负责动画及控制台显示；DesktopTasks 负责桌面安装任务身份、互斥和状态；宿主安装终端桥接继续承载真实运行，必要时只增加本地生命周期查询。Service 不因隐藏窗口而取消；shell、输入、存储及组件下载语义不变。归档与启动入口只增加真实忙碌互斥，不加入安装清单预检。无 HTTP、权限、签名或发布配置变更。

## 验证
覆盖首次提交终端尚未创建、隐藏后点击、多次快速点击、Activity 重建、安装成功、失败重试、宿主提交失败和终端异常丢失；断言每个活动安装只有一次宿主提交且复用同一 ID。编译 Java/XML 并运行相关状态及任务测试。真机人工回归检查动画、原控制台日志连续性及安装不中断；无设备实测时明确记录。Harness bootstrap、strict gate、OpenSpec CLI 和基线 specs 当前缺失，不声明严格门禁通过。

## 四组合审计后的批准范围

用户已批准 native/proot × Wine/desktop 的审计修复。Wine 保留现有动画与控制台，修复 API 至服务落盘之间的任务 ID 空档，提交前原子持久化 QUEUED 任务，提交失败落 FAILED；服务接收已有同 ID 任务并继续准备。公共安装入口识别 Prefix 父任务，允许其已登记的组件依赖。安装中点击卡片、编辑或删除入口均优先恢复该安装会话，禁止无意中断；已进入编辑页的加载流程也检查并回到安装控制台。桌面安装前记录唯一任务并复用；宿主暴露真实终端创建前的有限期提交状态，过期或丢失须失败并取消迟到任务。所有背景状态仅查询真实任务，无启动安装清单检查。
