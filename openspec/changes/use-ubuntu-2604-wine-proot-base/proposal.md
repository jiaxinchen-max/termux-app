# Wine PRoot 底包统一为 Ubuntu 26.04（用户已确认实施）

## 目标与现状

用户要求 Wine PRoot 与 Desktop PRoot 使用相同的 Ubuntu 26.04 底包。Desktop 的安装脚本已固定 `ubuntu:resolute`；Wine 当前仍用 Debian 13 的预装裁剪镜像，配方版本为 12。此次统一发行版及其来源，Wine 继续使用独立的精简游戏镜像，不与某个桌面容器共用可写根目录。

## 用户可见变化

- 全新 Wine PRoot 和用户显式重建的基础环境改为 Ubuntu 26.04 LTS（Resolute），保留现有 Wine、翻译器、图形和音频选项。
- 继续下载预装裁剪镜像，在安装阶段完成依赖、前缀及运行库准备；设备不重新执行客体 apt 安装或裁剪，启动不自动安装、修复或转换发行版。
- 用户明确不考虑历史数据兼容：仅接入新的 Ubuntu 配方，不兼容或迁移旧 Debian 容器、前缀和备份。显式基础重建沿用现有共享根替换事务，不增加新旧发行版并存和前缀自动复用逻辑。
- 重建先停止相关 Wine 会话并确认进程退出；安装只有成功或失败，失败不得留下新的就绪标记。
- APK 保持 `termux-app_apt-android-7-debug_arm64-v8a.apk` 原名。原有公开组件和旧镜像不改名、不覆盖；新增 Ubuntu 制品使用独立版本身份。

## 范围和非目标

范围包含可复现镜像构建、Ubuntu 运行依赖、三类前缀模板、组件索引、配方、安装/启动/备份/恢复身份与路径，以及真实 PRoot 验证。不升级 Wine/Proton/Box64 版本，不增加桌面软件，不做旧前缀自动迁移，不承诺所有游戏兼容，也不改变 Native Wine 或 Desktop 的现有根目录。

## 风险与回滚

Debian 上的 ELF 依赖、Mesa 路径、locale、Wine 模板来源不能直接改名复用，需要在 Ubuntu 上重新验证或重建。新镜像与模板独立发布；沿用共享根的暂存和 previous 回滚，失败恢复替换前的根与回执，不通过删除无关游戏数据解决安装问题。没有可验证的正式制品前，不切换生产默认下载地址。

## 文档和授权边界

本地运行环境变更不改变 HTTP API 合约，`api_docs=N/A`。发行版、重建与兼容规则属于用户可见行为，`product_docs=Required`，目标为 `docs/product/wine-runtime.md`，验收前一致性为 `Pending`。

用户已明确“推送完代码开始执行你的方案，但是不用考虑历史数据兼容性”，构成方案及实施确认，并覆盖本文件原有历史兼容设计。此前修复572b1151已推送；本轮开始实施。镜像Release发布、安装新APK与归档仍分别记录授权。
