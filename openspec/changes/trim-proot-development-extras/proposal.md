# 清理 PRoot 镜像残留开发文件

## 原因与范围

当前预装 Hangover 的 Debian 13 精简镜像仍含 Perl 开发头文件、纯 POD 文档和非中文／英文 gettext 翻译。上一轮清单盘点的候选展开体积为 19,827,051 字节。用户“先清除能清除的文件”确认先实施这批低风险清理。

仅对原镜像生成独立候选：删除上述普通文件及同语言 LC_TIME 中指向已选翻译的 .mo 链接，但保留法律声明、其他存活链接依赖及受保护文件。不删除 Perl 运行模块、LLVM／Gallium、Z3、字体、libc locale、Wine NLS、PE32／PE64 或 FEX／Box。删除量与压缩收益分别实测。

## 交付与边界

增加维护者离线裁剪工具、安全测试、候选镜像、配套描述及删除报告。任何输入异常立即终止，不重建、不降级。用户后续“直接发布后替换，我下载apk进行验证”批准将通过离线验证的候选替换到原资产仓库的原标签、原文件名，更新客户端描述和两个镜像索引，构建原名正常 debug APK 供手动安装；实际运行验收由用户完成。设备数据保持原状，此维护工具的输入核对不改变 App 已移除摘要／签名检查的行为。

无 HTTP 契约变更，api_docs 为 N/A。镜像体积影响用户存储，product_docs 为 Required，目标为 docs/product/proot-runtime.md；验收前一致性状态保持 Pending，不提前建立产品事实。

## 交付验收发现的安装阻断

设备任务 setup-ee7d8b41-3008-4b92-bb9d-dfd9ef540ff4 在 2026-11-11 失败。APK 使用新镜像描述，但组件准备直接接受旧 active 安装记录，导致旧包 323,406,172 字节与新描述 320,439,261 字节不符，尚未解压即停止。修复属于已批准“发布后替换、下载 APK 验证”的同一交付：显式 Build from network 必须准备当前镜像任务，不复用已安装记录或历史失败任务；常规程序依赖准备仍复用已安装组件。无自动版本／摘要升级，不修改校验策略，不清理设备数据。api_docs 继续 N/A，product_docs 仍 Required、Pending。
