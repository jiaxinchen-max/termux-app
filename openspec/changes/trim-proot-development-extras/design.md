# 设计

## 定向裁剪

采用独立离线工具读取已发布镜像及描述，不在运行中的 RootFS 删除。复用 prebuilt_rootfs.py 的清单格式验证和 minimize-rootfs.py 的客户机路径链接分析。只匹配 usr/lib 下 Perl 版本目录的 .h、usr/lib 或 usr/share 下 Perl 目录的 .pod，以及 usr/share/locale/<语言>/LC_MESSAGES/*.mo 中非 zh*／en* 的普通文件。完整清单发现同语言 LC_TIME/*.mo 链接引用这些翻译，将同名且目标属于已选集合的链接一并清理；不删除其他链接或目录。

从候选中排除法律声明和所有存活链接的解析路径。保护清单及运行清单不得发生删除或内容变化；验证其客户机路径最终指向的普通文件摘要。保留历史 sourceTrimReceipt，不将历史 Verified 误标为新候选运行验收结论。

## 归档与失败处理

逐成员核对原归档名称、类型、权限、大小与内容；拒绝额外、重复、缺失、硬链接、路径穿越、非零尾随载荷或解码失败。流式输出只更新 entries 和新描述中的大小、计数及摘要，其余清单字段保持原值。使用原打包压缩参数 zstd -T2 -6。独立临时目录全部成功复读后才成为候选目录；失败清除本次临时输出，源包始终只读，已有输出不得覆盖。

报告包含逐项删除原因、保留原因、各分类展开收益、实际压缩收益、保护文件数量、完整成员核对结果，以及运行验收 Pending。仅维护者离线制品核对使用摘要，不改 App 校验逻辑。保持现有镜像 ID、文件名和版本号，候选目录与线上资产分离。

## 验证与回滚

安全测试覆盖允许与禁止删除、中文英文保留、法律文件、普通及目录别名链接、PRoot .l2s、保护路径、畸形归档、损坏内容和失败不留候选。对真实镜像核对所有保留文件、权限和链接，保留 1594 个 prefix 来源文件及运行守卫。完成实际候选恢复／全量文件核对，不把静态一致性等同于 Wine 运行验收。

用户追加批准发布和替换。更新客户端 runtime-rootfs-v12/image.json、客户端 index-v1.json 中镜像条目的 size／sha256，以及维护用 prebuilt-rootfs-index-entry.json；镜像 ID、组件版本、下载 URL、文件名和 prefix 来源保持原值。构建原名 arm64-v8a debug APK，原签名，禁止 testOnly。核对 APK 内两份资产与源码一致，执行现有镜像身份和安装回归。

原资产仓库 jiaxinchen-max/termux-app-packages 的 rootfs-debian13-hangover-pdb2-minimal-v2 标签是发布目标。使用 GitHub Release 资产上传及重命名操作：先暂存上传新镜像并核对远端摘要、大小，保留原资产直到新包上传完整；再将新包切换到原文件名并删除临时旧包，最终标签只保留正式原名资产。公开 URL 下载核对后才交付 APK。发布时短暂切换窗口若失败，使用本地保留的原包与发布元数据恢复该 URL；这是发布恢复措施，不增加 App 运行回退或自动升级。

受保护资产影响为定向裁剪镜像及对应描述变化，先前 1594 个 prefix 来源及全部运行文件核对不变；验证依据为离线清理报告、完整恢复记录、APK 资产核对及发布后下载核对。回滚为恢复原包及备份的三个索引／描述文件，设备与用户数据不变。源码工具回滚为移除新增工具及其测试。用户本轮批准发布替换和 APK 编译交付，未授权 Git 提交、推送、设备操作或归档。产品文档一致性与真实运行验收继续 Pending。

## 显式基础镜像构建修正

RootfsSetupForegroundService 仅在待准备的 baseOnly 任务向 RootfsRuntimeComponentPreparer 传递显式重新准备标志。该路径为每个基础组件创建使用当前内置索引的新任务，等待该任务 INSTALLED 且 active 目录存在；不得因已有 active 提前返回，也不得重试其他历史构建创建的失败／暂停任务。同一父任务中断恢复时只查询已登记的自己的子任务，复用其完成状态或等待其执行；它已经失败／暂停／取消时立即停止，不自动重试。普通程序初始化传递 false，保留已有安装和恢复规则。沿用 ComponentTasks.enqueueRuntimeDependency，先登记父子关系，使用现有串行下载与安装事务；不增加独立镜像安装入口，不使用 requireManageable 或自动版本判断。相同有效缓存仍由现有下载器复用，过期大小的包按当前描述重新下载。

为真实回归测试抽离命令发送边界，生产仍调用原 ComponentTasks；测试以真实文件任务仓库、下载器、安装器与协调器执行同版本新旧镜像替换，覆盖旧 active、旧失败任务、有效缓存、下载失败终止及普通准备不升级。保持失败停止策略与组件身份、原资产 URL。镜像内容无需再次发布，仅重新构建原名 APK。回滚恢复两个 Java 准备文件及 RuntimeInstallationGate 查询可见性；不会更改已发布镜像。设备仅只读取证，用户继续手动安装与界面验收。Harness 严格脚本和 OpenSpec CLI 缺失，明确记录不可用。
