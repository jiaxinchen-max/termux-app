# 可见session接线

终端重建入口继续把统一install和1.04.10-0 deb复制到既有暂存目录；将后台CommandUtils调用替换为Activity委派至终端session客户端的新安装入口。该入口复用普通交互session创建方法，不使用受自动关闭设置影响的工具箱快捷方法。新session由TermuxService按既有普通终端生命周期管理，其他session保持原状。

关闭偏好设置抽屉并显示终端页面。输入一条命令：打印安装开始提示，在if分支内以独立sh执行明确指定的install；成功打印成功，失败直接打印失败退出码。路径及本地化文本按shell单参数引用，避免空格、单引号、美元符号或命令替换改变命令。子脚本失败仍遵循其set-eu规则，父交互shell保留，不自动关闭或重试；安装完成回到提示符，用户自行结束普通session。

复用既有服务可用性检查、8个session上限和新会话选择，已有错误提示保持生效。不新增service进程模型、固定等待、弹窗轮询或专用日志页面。新中英文文案覆盖session名、安装开始/成功/失败。

验证实际入口调用到普通session执行边界、关闭抽屉及显示终端；使用本地真实shell运行捕获命令，验证输出、失败退出码、特殊路径引用和父shell仍可继续执行。复测原安装流程的隔离APT测试，构建原名、原签名、非testOnly APK。仓库缺少protected-path策略和严格Harness门禁，记录缺失，回滚本变更Java/文案/测试即可，不修改用户数据。
