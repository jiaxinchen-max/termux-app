# 文件管理器菜单与文件详情优化

## 问题与目标

用户提供的两张截图显示：条目长按菜单首行重复显示长文件名，拉宽菜单；菜单及详情弹窗背景过透，底层文件列表干扰阅读；普通 `.archive` 文件虽然被识别为非 Windows 可执行文件，仍出现 Wine 导入按钮及 C: 盘提示。

本轮目标为：条目菜单直接从操作项开始；提高文件管理器弹层可读性；普通模式下单击文件显示文件信息，只有实际识别为 Windows 可执行程序时提供 Wine 导入入口与提示。长按菜单与详情使用相同判断。

后续变更 `unify-termux-ui-dialog-opacity` 已获2026-11-18用户批准：原局部90%视觉方案由模块统一85%不透明方案替代。本文相应视觉要求已同步，历史APK和测试证据仅说明当时实现。

## 拟议行为

- 文件和目录的条目菜单去掉禁用的名称首行，保留打开、复制、剪切、删除、多选等操作。
- 文件管理器条目菜单和对话框共用模块85%不透明的面板底色，适配亮色和暗色主题、横竖屏及无系统模糊的环境。
- 普通文件详情保留文件名、大小和修改时间，只有关闭动作，不再展示 Wine 提示、非可执行程序提示或导入按钮。
- 按实际 PE 可执行程序结构检测导入资格，不以扩展名决定；伪装 `.exe`、压缩包、文本、DLL、驱动和检测失败的文件不显示导入。有效 Windows GUI／控制台程序显示原有后端对应的 Wine 导入动作和相关提示。
- 多选模式下点击仍切换选中，单击目录仍导航，系统“打开”仍调用应用选择器。

## 范围与影响

主要修改 `GameFileManagerActivity`、`PeExecutableInspector`、文件管理器主题／背景资源及相关回归测试。文件管理器局部菜单几何保留，面板填色由后续统一变更共用 Wine／Desktop 等页面弹层资源。既有导入 Native／PRoot 选择及配置草稿流程继续复用。

`api_docs: N/A`：仅 Android 本地交互与文件内容识别，无 HTTP 契约变更。`product_docs: Required`：最终验收后更新 `docs/product/file-manager.md`，一致性当前为 Pending。
