# 游戏控制器

## MODIFIED Requirements

### Requirement: 手柄设置统一位于运行时控制器页

系统必须从编辑页 Advanced 删除 Enable XInput、Enable DirectInput 与 DirectInput 映射，将三项放入运行时抽屉 Controller 页；Function Library 仅保留独立 DLL 加载顺序。

#### Scenario: 打开编辑页及运行时抽屉
- 当用户查看任意 Native／PRoot／Hangover 游戏的 Advanced
- 则不存在三个手柄设置入口。
- 当用户进入运行时 Controller 页
- 则看到两个独立接口开关与映射选择，触控布局 Off 不影响这些设置的可操作性。

### Requirement: 接口开关保存后立即应用

两个开关必须按游戏独立保存，保存成功后通过现有协议启停相应接口。失败时显示错误并保持先前会话及保存值，不生成替代配置。Activity 重建必须恢复已成功保存的接口状态。

#### Scenario: 单独停用 XInput
- 当用户关闭 XInput 而保持 DirectInput 开启
- 则成功保存后当前会话仅允许 DirectInput，下次启动也保留此选择。

#### Scenario: 存储失败
- 当配置丢失、无效或保存失败
- 则显示错误，不修改当前会话，也不创建替代配置。

### Requirement: 映射独立保存且下次启动生效

系统必须区分当前冻结映射和下次启动保存映射，显示相应生效提示，不改变本局已创建的 DirectInput 设备格式、不重建 prefix、不初始化 Wine、不强制重启。选择 XInput 布局或 DirectInput 布局不得改变接口开关、触控布局或 DLL 顺序。

#### Scenario: 选择新映射及触控布局
- 当当前会话为 XInput 布局，用户保存 DirectInput 布局，然后选择其他触控布局或 Off
- 则保存映射仍为 DirectInput，本局仍为 XInput，页面显示当前与下次启动值。

#### Scenario: 重绘及重建
- 当待生效映射与当前不同，页面重绘或 Activity 重建
- 则当前映射仍取冻结快照，下次启动映射取成功保存的配置；下次新启动采用保存值。

### Requirement: 控制器页使用紧凑且明确的开关布局

XInput 与 DirectInput 的独立接口开关必须在同一行等宽两列显示，不重复显示立即生效说明。DirectInput 映射必须使用单个滑动开关，在 XInput 与 DirectInput 中二选一，直接标明两个位置含义，无需弹窗。仅保留下次启动及必要当前映射的简短状态。Controller 页不得显示页首和指针选项的说明段落；错误、空列表及功能标签保留。

#### Scenario: 直接切换映射
- 当用户滑动或点击映射开关
- 则按目标位置保存唯一映射，当前会话映射不变，保存失败还原先前位置并显示错误。

#### Scenario: 窄窗口与页面重绘
- 当用户在窄窗口打开页面或保存后重绘
- 则两个接口开关保持同一行等宽两列，标签可完整阅读，映射位置与成功保存值一致。

### Requirement: 保存映射不影响无关开关的显示

映射保存开始、成功或失败时，XInput／DirectInput接口开关必须保持原控件、选中值、可用状态和透明度，不能因整页重建或全局忙碌状态闪动。程序化同步不得触发额外保存或运行时接口更新。不同字段的排队保存不得相互覆盖；初次读取尚未完成时维持原禁用规则。

#### Scenario: 映射正在保存
- 当用户切换映射且磁盘保存尚未结束
- 则只禁用该映射选择，接口开关保持显示和可操作，保存成功后原位更新映射提示。

#### Scenario: 保存失败或连续操作独立接口
- 当映射保存失败
- 则原位恢复上次保存映射并显示错误，接口开关不变。
- 当映射保存中用户切换一个接口
- 则串行保存两个字段，较早回调不重置另一项待保存位置，最终保存值和即时接口状态正确。

### Requirement: 运行时抽屉通用分类名称一致

游戏与桌面运行时抽屉原 Operation 分类及对应面板标题必须统一显示英文 Common、简体中文“通用”，保留既有操作内容和导航行为。

#### Scenario: 打开抽屉或从子页返回
- 当用户打开游戏或桌面抽屉的通用分类，或从游戏控制器子页返回
- 则分类菜单和对应面板标题使用同语言的 Common／通用，原有动作继续可用。
