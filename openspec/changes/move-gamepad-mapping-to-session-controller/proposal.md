# 将手柄设置迁移到运行时控制器页

## 原因

用户已批准把手柄模式入口从游戏／容器编辑页迁移到运行时抽屉的 Controller。上次 APK 仅完成 DLL 默认加载顺序，遗漏迁移；本次截图明确指出 Enable XInput 与 Enable DirectInput 两个开关也必须移出 Advanced。

## 确认范围

从 Advanced 删除两个接口开关和 DirectInput 映射行，统一放入运行时 Controller 页。两个接口独立按游戏保存，保存成功后立即通过现有协议启停。映射选择按游戏保存，滑动位置显示保存的下次布局，变更时补充当前布局；由于 DirectInput 设备格式在创建时固定，映射变更下次启动生效，不强行热切换、不重启游戏。触控布局仍即时切换，不覆盖已保存映射。

Native、PRoot、Hangover 共用入口与保存规则。保留独立的 DLL 加载顺序及既有显式配置，不修改 DLL、winhandler、prefix 或组件版本，不添加兼容迁移、自动重建或隐式回退。

## 授权及文档

以前文“批准实施”和本次纠正遗漏为本范围实施授权，无需再次确认。无 HTTP 契约变更，api_docs 为 N/A。用户可见入口变化，product_docs 为 Required，验收后维护 docs/product/game-controllers.md，当前一致性 Pending。Harness 引导／严格脚本、OpenSpec CLI 和产品基线缺失，记录文件级审查及本地验证，不声称完整门禁通过。不含提交、推送、设备操作或外部发布。

## 已确认的界面精简

用户进一步明确要求两个接口开关一行两列，DirectInput 映射采用单个滑动开关，并删除 Controller 页说明文字。本次仅调整既有入口排版与文案：接口标签为 XInput／DirectInput，不重复解释立即生效；映射两端标明 XInput／DirectInput，仅保留“下次启动”及存在差异时的当前值提示。删除页首、指针选项的说明段落，保留必要错误和空列表提示。该具体请求作为已批准迁移范围内的界面细化授权。

## 已批准范围内的闪动缺陷修复

用户反馈切换Input Mapping会让上方XInput／DirectInput开关一起闪动。当前保存开始与结束均重建整页，并全局禁用／启用三个开关，与已批准的映射、接口相互独立要求不符。本次纠正该实现缺陷，沿用此前独立开关及紧凑布局的确认，不新增功能、协议、兼容处理或权限；直接完成局部修复和正常APK交付。

## 已确认的抽屉名称调整

用户明确要求将抽屉 Operation 改名为 Common（通用），作为已批准运行时菜单范围内的文案细化授权。游戏与桌面抽屉共用菜单资源，两处菜单和对应面板标题统一使用英文 Common、简体中文“通用”。仅改资源值，保留入口、内部标识和动作。无 HTTP 契约变化，产品一致性仍待用户验收。
