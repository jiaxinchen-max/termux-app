# 设计

## 入口及生效时机

GameRuntimeOptionsView.renderAdvanced 移除两个接口开关及映射选择。GameControllerPanel 在触控布局列表之前将 XInput、DirectInput 两个接口开关等宽并排，随后显示 DirectInput 映射滑动开关。两个接口开关始终独立于触控布局 Off，不因隐藏虚拟手柄而禁用；配置读取失败则禁用设置并显示错误，不生成默认配置。

运行时更新接口不得清空其他接口的客户端身份。关闭接口时先向已订阅客户端发送中立输入再发送不可用状态，释放 DirectInput 缓存的按键；保留订阅，重新启用后继续推送。使用现有 64 字节协议，无需重编 DLL。

接口选择在现有串行 IO 队列读取最新配置、只修改目标接口、保存后调用 X11SessionView.setInputApis，使协议立即生效。页面按成功保存且应用的状态显示；保存失败不修改会话并还原开关。Activity 重建重新读取已保存接口选择并应用，保持运行时选择。

映射固定从冻结 LaunchSpec 读取为当前会话值，选择仅修改磁盘配置的映射前缀，滑动开关显示成功保存的下次映射，端点标签为 XInput／DirectInput，状态提示“下次启动生效”；与当前映射不同时补充“当前 XInput／DirectInput”。补丁在设备创建时为两种布局生成不同的轴键对象，不能保证已创建设备安全热切换，因此明确下次启动生效。

## 持久化及隔离

所有配置修改在同一个 IO 队列执行，写入前读取最新完整配置，仅替换目标字段，避免映射、接口及触控布局互相覆盖。保存触控布局时保留最新磁盘映射；即时应用布局时采用当前冻结映射，包括 Off。页面重绘不把待生效映射当成本局实际映射。活动销毁后不操作其 View。

## 范围与回滚

仅修改 Android UI、按游戏配置读写辅助类、现有输入桥的接口更新、资源及测试。不改签名、发布配置、JNI、DLL 二进制、资产或启动脚本。回滚还原本次代码、资源、测试；保留此前无效配置隔离及 DLL 默认顺序修复。磁盘格式不变，无需迁移。

## 验证

覆盖四种 Wine 编辑页均不再出现三个入口；运行时两个独立开关保存后协议调用、保存失败不改变会话、Off 下仍可启停、映射当前／下次启动区分、触控布局与映射连续保存不覆盖、页面重建恢复、配置缺失／无效不回退。完成局部测试后运行相关模块测试及正常 arm64 APK 构建，核对原文件名、签名和 testOnly。设备验证由用户手动进行。

## 界面精简设计

两个独立接口开关以等宽两列水平排列，标签缩为 XInput／DirectInput，无说明副文案。映射区域使用单个可拖动的原生 SwitchMaterial，关闭位置对应 XInput、开启位置对应 DirectInput，两端直接标注模式，无弹窗。简短提示下次启动生效；待生效值与当前不同时追加当前模式，避免把待生效值误认为本局状态。保持读取中禁用、保存失败还原和错误提示。移除 Controller 页首说明、Input options 下说明和三个指针选项说明，不改选项禁用条件。使用实际 Activity 回调测试单次保存、独立启停、映射切换失败还原与窄窗口两列布局。仅 UI 资源及相关测试有增量，无存储、协议或资产变化。

## 保存期间保持无关控件稳定

根因为GameControllerPanel.settingsLoading／settingsSaved／settingsFailed调用render重建整页，且settingsBusy禁用所有设置。改为保留接口行、映射行和三个SwitchMaterial实例，读取及保存回调仅更新既有控件状态和映射提示，不重建布局列表或其他行。状态同步时阻止触发用户监听，数值相同不重复setChecked，避免无关动画和重复保存。

初次读取仍同时禁用设置。后续保存按加载、映射、XInput、DirectInput、触控布局区分进行中状态，仅禁用正在保存的对应设置；映射保存不改变接口控件的选中、可用性及透明度。不同字段继续复用现有串行IO队列，回调更新成功保存快照，但不得用较早快照覆盖另一个仍在保存的开关显示。失败只恢复失败字段及显示原有错误；其他接口及当前会话映射不变。完整页面重绘需要时复用这三个控件，不新增存储格式或运行时协议。

回归测试使用真实Activity和磁盘存储，在串行IO中设置可控等待，检查保存开始、结束及失败时控件身份、选中／可用／透明状态；覆盖映射待保存期间操作接口以及无程序化回调重入。仅修改GameControllerPanel、GameSessionActivity和相关测试，不改wine-bridge或DLL。回滚仅还原本次局部UI更新，不撤销工作区其他改动。

## 抽屉名称统一

修改默认与简体中文资源中的 local_game_session_operation、local_game_session_operation_title 和 desktop_session_operation_title，共六个资源值。游戏及桌面抽屉菜单、面板标题同步显示 Common／通用；从控制器子页返回时仍引用原资源键，自动保持一致。无需修改布局、代码标识、事件处理或存储。回滚仅还原六个文案值。

本次为可逆的低影响文案变更，不增加复述资源值的单元测试。核对资源 XML、所有引用、打包后中英文资源及正常 arm64 APK 的签名、testOnly 和资产载荷。严格 Harness 和 OpenSpec CLI 仍缺失，记录本地证据，不替代用户设备验收。
