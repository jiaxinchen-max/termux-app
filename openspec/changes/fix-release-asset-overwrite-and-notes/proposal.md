# 修复同标签重复发布与发布说明换行

用户明确要求同一 tag 的 Release 附件可原地更新，避免重复上传冲突，并要求发布说明显式使用 \n 换行符。本轮按这两个明确的 CI 修复要求实施，承接已确认的双语说明及原有 APK 命名规则，不涉及应用业务代码。

当前上传 Action 未开启覆盖，且其 uploadChecksums 直接上传 CHECKSUMS 文件，即使启用 overwrite 也无法覆盖校验附件。现有手动输入使用真实多行默认值，网页输入后可能变为一行；发布脚本又用 printf 原样保存，未解释字面 \n。

目标为同标签重跑时覆盖本次同名 APK 和三份校验文件，保留 Release/tag 及其余附件；新标签仍能创建 Release。中英文说明默认值显式编码换行，上传前仅将字面 \n 还原为真实换行，保留其他反斜杠文本。保持现有构建矩阵、APK 文件名/类型与校验文件名称和条目格式。

不执行实际发布、不创建或移动 tag。用户随后明确要求“直接推送”，授权提交本次 workflow 修复及对应规划文档，并推送至既有 master-x11-submodule-tmp 分支。本轮仅修复构建/CI，api_docs 与 product_docs 均为 N/A。覆盖上传会先删除同名资产再上传，期间有短暂不可下载窗口；可通过重跑恢复。源码回滚为恢复本次 workflow 修改，已发布资产不在本轮操作范围内。
