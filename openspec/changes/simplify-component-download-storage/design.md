# 设计

下载服务只构造 Environment.DIRECTORY_DOWNLOADS/Termux/components。统一路径定义，删除 migrateVerifiedArchives 调用及实现、Download/component固定查找与getExternalFilesDir回退。检查目录创建和写权限；捕获创建/访问失败并转为可读的本地化存储权限提示，不仅显示内部错误码。权限不足立即失败，授权后由用户重试，不切换目录。

现有Wine/Box64手动安装入口继续通过系统文件选择器取得所选URI及读取权限，来源无需与缓存目录相关。移除不再使用的固定目录恢复代码及专属测试，保留下载目标自身的断点续传和完成包复用；不新增全盘扫描、兼容迁移、自动重试或技术配置项。

验证：固定目标路径、不可写失败与错误提示、无迁移和无私有目录回退、用户选择不同目录的本地包仍可安装，以及既有缓存复用与下载流程。编译固定命名arm64普通debug APK，由用户手动验收。回滚撤销代码修改，不处理已存在的下载文件。

## 备份保存和恢复
集中定义共享Download/Termux/backups路径，RootFS与C盘备份直接生成到该目录，沿用可识别类型和时间戳命名，创建时避免同名覆盖。移除备份保存目录及名称选择入口，不增加rootfs/cdrive子目录。恢复时以普通列表列出固定目录内匹配扩展名的备份，保留覆盖现有数据前的确认；空目录明确提示没有备份。列表允许选择备份版本，但不允许浏览目录或输入路径。权限失败停止并给出可读授权提示，授权后用户重试。

同步RuntimeBackupFlow、WineCDriveBackupFlow和LocalGamesActivity调用，检查服务层目标边界，避免仍接受任意外部备份输出。保留私有任务日志和恢复暂存的原有职责，不移动旧备份文件。验证自动保存、同名保护、固定恢复列表、无备份和权限失败，以及外部组件仍能选择任意来源。

## 文件命名范围
实施前形成App自有game-/games-文件名清单，区分输出包名、模板缓存文件、内部管理文件和上游资源名称。App自有文件更名为wine-后同步所有生产/消费端及测试。目录（如games-shared-rootfs、.games-runtime）、命令参数、会话标签、字段和组件ID不按文件名规则机械替换。镜像内部管理文件涉及发布资产时需验证资产生产链与提取流程一致，不允许产生新代码读取不存在文件的情况；组件URL不因重命名本地文件而拼接改写。手动组件文件名无需满足wine-规则。

用户要求所有备份保存固定位置，桌面环境导出同样使用固定backups目录；桌面归档导入属于外部发行版安装，保留来源选择。
