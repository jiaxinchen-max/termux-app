# 设计

使用 desktop_install.sh 作为统一初始化成功边界：写入安装成功标记和 INSTALL_DONE 之前调用统一检验入口。新建保存已自动进入安装流程，设置保存保留支持矩阵校验，渲染器改变或启用 USB 存储时自动进入安装初始化并打开既有终端；仅修改名称和分辨率不重新安装，不在启动补检。

Android 会话页面的轮询只读取运行进程/状态/就绪结果，启动互斥仅读取停止状态，不触发 DesktopEnvironment 安装文件清单检查；桌面列表的安装状态展示保留。

GNOME 启动器移除 rootfs/ICD/GIO 静态扫描与 glxinfo 合成探测，PRoot Ubuntu 双重文件检验移至安装。Hyprland 启动移除 manifest、依赖导入以及宿主/测试窗口 GPU 探测；初始化完成组件与依赖检验，并在选择 Zink 时执行宿主 dma-buf 和容器无显示器 EGL 能力检验。XFCE 的 GIO 文件检验也移到初始化。

Plasma 初始化从固定 r28 包内原始脚本生成应用专用启动脚本与渲染环境脚本；生成前固定 SHA 验证，精确替换受审查静态检验/探测块，保持启动环境和进程监督逻辑。原始包文件不改，保留为显式诊断来源。归档恢复的宿主前置初始化也生成相同 Plasma 脚本，不修改导入的容器。容器所有依赖、Qt Wayland 插件和 polkit 身份设置在安装助手完成，删除启动补包和身份修复。

显示连接和测试窗口必须依赖正在运行的显示服务，初始化改用无显示器 EGL 能力探测，实际会话只依据真实 compositor/客户端失败结束，不通过测试窗口确认。不得将无显示器检验声称为实际窗口呈现验证。无能力回退，无启动缓存。

风险与回滚：设备或安装内容在初始化后变化，实际运行可能失败；需用户重新初始化，不能启动自修复。包升级造成脚本 SHA 变化时初始化明确失败，更新审查后的转换规则。回滚应用脚本即可恢复旧启动行为。未改权限、证书、原生代码、包配方；既有其他变更保持。严格门禁工具缺失记录不可用，设备未验证如实报告。
