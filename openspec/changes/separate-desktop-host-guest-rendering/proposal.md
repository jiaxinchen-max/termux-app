# 分离桌面宿主与容器渲染配置

## 问题与目标
用户指出创建容器桌面页面将宿主显示链路与容器内部渲染混用，并明确要求修复。截图所选XFCE的“容器内部渲染器”实际控制宿主Xlorie；Plasma同一个glMode同时控制宿主KWin和容器Qt；GNOME只有在启动规格里推导出配对；Hyprland已经分开启动变量，但界面仍沿用一个glMode。

本轮将宿主显示端/合成器渲染与容器桌面/应用渲染明确分开，分别持久化、展示、校验及传递。System EGL只作为宿主渲染名称，容器glibc默认模式称“默认”，不冒充直接使用Android系统EGL。根据实际架构说明容器中是否存在合成器。

## 拟采用规则
采用“分开配置，保留当前支持的组合”。宿主System EGL优先用于已支持的组合；不将所有宿主强改System EGL。GNOME的Zink/dma-buf现有配对必须保留。用户已批准按当前支持矩阵实施。

创建、设置和卡片展示宿主及容器两个明确值；原生桌面只有宿主。不兼容组合明确阻止保存和启动，用户主动选择，不自动改另一个值或回退。XFCE容器尚无独立图形加速契约，容器一行显示默认及限制；不提供虚假的Zink/软件加速承诺。

## 格式与验证
仅支持当前schema3配置、version2归档及version3启动规格，不迁移或兼容旧数据。复制、重命名、输出修改和恢复保留当前两层配置；旧格式、未知格式与冲突字段明确拒绝。测试覆盖当前格式往返、安装驱动路由、宿主与容器环境隔离、错误状态、GNOME配对及Hyprland严格失败。构建ARM64候选APK，设备结果逐项记录，不把fixtures或编译当作设备通过。

## 边界与风险
不修改native子模块和组件二进制，不新增未经验证的跨层组合，不承诺所有容器都能用System EGL搭配GPU。需要扩展缓冲导入能力时另行说明并确认。不主动删除容器目录或用户文件；旧配置及归档不在本轮支持范围。
