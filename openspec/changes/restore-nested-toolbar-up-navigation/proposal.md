# 恢复子菜单与文件浏览器的上一级按钮

## 原因

用户反馈多级菜单和文件浏览器仍需要工具栏返回按钮。截图中的“Core components”属于设置子页，当前 `LocalGamesActivity.updateChrome()` 却统一清除了导航图标。文件浏览器虽然保留 `navigateUp()`，共享 `CollectionToolbar` 构造时也会清除图标，且没有绑定工具栏上一级点击事件。

## 变更范围

- 设置中的“Core components”和其下的 Native、PRoot 页面显示左上角返回箭头，每次点击仅返回一级。
- 文件浏览器进入任意实际目录后显示返回箭头；普通目录返回父目录，三个入口各自的根目录返回入口列表。入口列表本身不显示上一级箭头。
- 复用既有父级导航、图标和无障碍描述；横竖屏、页面恢复及深浅色保持一致。
- 保留已有组件版本页、编辑页及运行抽屉子页的返回按钮；根级全局导航和之前移除的悬浮菜单按钮不变。

## 文档和接口

不涉及 HTTP 契约，`api_docs` 为 N/A。用户可见导航行为发生变化，`product_docs` 为 Required，目标为 `docs/product/ui-navigation.md` 和 `docs/product/file-manager.md`；待最终验收后形成规范，当前一致性状态 Pending。

## 验收

设置三级菜单逐级返回正确；文件浏览器逐级返回且不越过三个根目录边界；旋转、重建和深浅色下图标正确；工具栏现有文件操作仍可用；按原文件名生成可正常安装的 arm64 APK。
