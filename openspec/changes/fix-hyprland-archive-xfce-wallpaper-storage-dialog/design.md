# 设计

## Hyprland 完整归档链路

统一管理菜单、实际发行版检查、元数据校验和恢复初始化的支持集合，新增 Ubuntu/resolute 的 Hyprland PRoot；Native 和废弃的独立 GNOME 仍不开放归档。

为 Hyprland 增加明确的归档格式分支，记录 `hyprlandRuntimeId`、`hyprlandThemeId` 以及实际桌面 schema；现有其他桌面的格式保持原样。解码必须验证字段集合、类型、组件兼容关系和规范序列化，不能丢弃未知字段或静默回落到默认主题。导入生成新 ID 与 alias 时必须完整复制两个组件字段；名称及重名数字后缀继续使用原有规则。沿用归档链接、目录边界、大小、完整性及事务发布规则，不扩大可执行来源或解包权限。

在 `host-prerequisites` 分支复用原 Hyprland 固定组件下载及校验逻辑，按备份中的合成器、主题身份准备宿主。已满足的组件直接复用；不得调用完整容器安装器、创建额外容器或执行 guest apt。完整安装与宿主准备须共用窄的组件准备函数，避免重写一条编译/发布链。实际组件仍在资产库按需获取。

恢复 wrapper 传递新桌面 ID、正确的 `.hyprland-ready` 路径、输出尺寸、刷新率及组件身份；在本地恢复阶段重建新身份的宿主会话文件。初始化失败、取消或宿主组件不兼容时不发布成功记录，复用原事务清理本任务独占目录，保留原容器和备份。测试必须覆盖全新宿主和已有宿主，不能仅以菜单可见判定成功。

本次只承诺完整容器与已声明桌面参数的归档，不把宿主用户目录、其他桌面配置或组件二进制塞进容器归档。普通启动继续只消费已保存结果和运行时服务，不新增安装、初始化、自动重试或渲染回落。

## XFCE 默认壁纸

现场缺失的是 Ubuntu 版 xfdesktop 编译使用的 Xubuntu 默认路径，发行版内已有 greybird 与 XFCE 图像。仅在容器安装、保存或恢复阶段准备受管理的默认路径，使其引用容器内现有且实际可解码的壁纸。优先复用现有资源，不下载或内嵌新图像。

已有有效默认文件、用户指定壁纸和用户 XFConf 配置保持原样。写入前约束父路径及链接目标在容器内，拒绝越界链接或非预期同名文件，不从宿主解引用容器绝对链接。恢复新身份沿用相同准备步骤。若现有图像仍存在解码问题，先通过独立读取探针证实，再在规划范围内确定所需最小适配，不凭猜测替换图像库。

## 外接存储弹窗

只为当前 USB 管理弹窗提供实色、带边界的浅色/深色表面，避免改动全 App 玻璃效果。程序化文本、复选框及按钮使用弹窗的主题上下文和 Material 控件，保证文字、背景、禁用态和触摸反馈一致。

把“当前环境不支持”“需要先关闭桌面”“尚未启用”“正在准备”“可刷新/操作设备”分别映射到明确文案和控件状态。Hyprland 和当前 Ubuntu GNOME 不再显示 Plasma/Solid 提示；不支持的环境不展示误导性的缺包安装引导。XFCE 启用后才提供安装动作，运行期间不允许更改会话配置，Android USB 权限仍由系统弹窗和用户决定。

刷新与用户变更操作应有明确的状态管理和异常出口，读取依赖/会话状态抛错时也必须回到可重试状态。关闭弹窗后不得再更新 View 或提交新工作。保留设备授权、挂载、卸载和弹出各自的真实支持条件，不以视觉可点击替代功能可用性。

## 验证、影响和回退

验证包含：Hyprland 两种主题元数据与真实归档往返、组件字段及非默认主题保留、新身份会话准备、缺失组件宿主准备且不安装 guest、失败不发布；既有三类容器归档回归；XFCE 缺省路径、已有自选壁纸、非法链接、重复保存；弹窗日夜主题截图、支持和不支持环境、操作禁用原因、刷新异常与关闭生命周期。交互验证前 force-stop App，从实际 UI 进入，不改变用户默认入口；涉及导入使用独立测试目标，保留原容器与备份。

预期涉及 `DesktopArchiveDistribution`、`DesktopArchiveMetadata`、`DesktopArchiveEngine`、`DesktopRestorePrerequisites`、`desktop_install.sh`、`desktop_initialize.py`、USB 弹窗及必要纯策略/主题资源和聚焦测试。没有发现仓库保护路径清单；不修改七个既有脏子模块。若发现新的保护规则，先记录影响和适用授权。

回退撤销本变更的源码与新增归档支持，保留已导出的文件。新增格式在旧 APK 中应被明确拒绝，不能误读为其他桌面；保留一个新 APK 用于恢复新 Hyprland 归档。实机验证备份本次拥有的配置；只回退本次修改，不清理或重装原容器。最终构建固定名非 testOnly 的 arm64 APK，代码按既有授权推送；组件无需重新编译时不发布重复 DEB。
