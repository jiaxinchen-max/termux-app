# 桌面容器管理修复

## MODIFIED Requirements

### Requirement: 四类当前容器归档范围一致

系统 MUST 为当前 Ubuntu Resolute 的 XFCE、Plasma、Ubuntu GNOME 和 Hyprland PRoot 提供一致的归档入口、实际发行版校验及完整恢复流程。本需求扩展历史规划中 Hyprland 不开放归档的范围，保留 Native 和废弃 GNOME 的限制。

#### Scenario: Hyprland 导出恢复
- **WHEN** 用户导出停止且满足原有互斥与 USB 关闭条件的 Hyprland 容器并独立恢复
- **THEN** 保留容器应用、用户文件、名称、显式渲染参数、合成器及主题身份；使用新 ID 和新 alias，名称冲突添加数字后缀。

#### Scenario: 未知主题或非法归档
- **WHEN** 归档包含未知/不兼容组件、错误 schema、额外字段、越界链接或超限内容
- **THEN** 明确失败，不替换为默认主题，不发布成功记录，不损害原备份或容器。

### Requirement: 恢复前完成宿主及会话准备

系统 MUST 在恢复发布前按归档声明准备必要的可信宿主组件，并在恢复阶段为新身份生成会话；不得重新安装 guest 或把初始化移入普通启动。

#### Scenario: 全新宿主恢复非默认主题
- **WHEN** 目标宿主缺少备份所选的合成器或主题
- **THEN** 从既有资产库获取并校验对应组件，复用已有正确组件，在新身份会话准备成功后发布桌面；不创建额外容器或执行 guest apt。

#### Scenario: 恢复失败或取消
- **WHEN** 宿主组件准备或本地初始化失败/取消
- **THEN** 不报告成功，按原事务规则回收本任务独占资源，保留其他桌面、原容器和原归档。

## ADDED Requirements

### Requirement: XFCE 缺省壁纸有效

系统 MUST 在容器安装、保存与恢复阶段准备实际存在且可解码的默认壁纸路径，优先使用容器内已有发行版图像，保留有效自选壁纸和用户配置。

#### Scenario: 最小 Ubuntu XFCE 缺少 Xubuntu 默认文件
- **WHEN** 当前缺省路径不存在且容器内存在适用壁纸
- **THEN** 保存阶段补齐受管理的缺省路径；下一次正常启动能显示壁纸，不在启动时下载或修补配置。

#### Scenario: 保留已有配置与目录边界
- **WHEN** 用户已有有效壁纸，或待写入路径含有越出容器的链接
- **THEN** 前者保持，后者拒绝并报错；不得写入宿主目标。

### Requirement: USB 弹窗可读且状态准确

系统 MUST 在深浅主题、无背景模糊能力时保持 USB 外接存储弹窗内容清晰、表面不透出下层卡片；可用、禁用及忙碌状态必须与真实后端能力一致。

#### Scenario: 不支持的桌面环境
- **WHEN** 打开 Hyprland、当前 Ubuntu GNOME 或 Plasma 的 USB 管理弹窗
- **THEN** 展示对应环境的准确限制，不把所有环境都解释为 Plasma，不引导安装不能使用的组件，不通过放开开关生成无法启动的配置。

#### Scenario: 支持的 XFCE 配置与设备操作
- **WHEN** XFCE 桌面已停止、没有变更任务且用户明确启用 USB
- **THEN** 允许准备依赖并按原系统授权流程操作；运行时修改限制与禁用原因清楚可见，关闭按钮可用。

#### Scenario: 异步失败或弹窗关闭
- **WHEN** 依赖或会话状态读取失败，或者用户在操作期间关闭弹窗
- **THEN** 前者显示可理解错误并恢复可重试状态，后者停止界面更新和后续刷新，不因异常让控件永久失效。
