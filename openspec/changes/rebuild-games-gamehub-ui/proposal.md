# Games 盖世式本地游戏体验重构提案

## 背景

上一轮 `redesign-games-consumer-ui` 只完成暗色主题、底部导航、导入 Hero 和两列封面网格。2026-08-28 对 5 分 06 秒盖世游戏完整录屏逐帧分析后确认，主要差距不是颜色，而是页面容器和信息架构：竞品本地 PC 游戏主链路是横屏游戏库、上下文启动弹层、横屏主从设置、分阶段启动和游戏内右侧控制中心。

## 目标

- 将 Games 改为横屏优先、横竖屏自适应的本地游戏 Shell。
- 游戏库以游戏内容和导入快捷入口为核心，组件和设置退出一级导航。
- 游戏详情和更多操作在当前游戏库上下文中展示；横屏使用 Modal，竖屏使用 Bottom Sheet。
- PC 引擎设置使用左侧分类、右侧内容的横屏主从布局，并复用现有 `RuntimeProfile`。
- 启动页以三阶段用户状态替代内部 task/stage/preflight 枚举展示。
- `GameSessionActivity` 增加覆盖 X11 画面的右侧控制中心，终端仍只作为可选日志入口。
- 保留现有 SAF、Repository/Orchestrator、组件断点续传/校验/安装回滚、持久 LaunchTask 和 X11 Host 能力。

## 非目标

- 不实现云游戏、社区、排行、账号、Steam/Epic 在线同步和布局市场网络服务。
- 不复制竞品品牌、商标、文案、封面或图标素材。
- 本 change 不新增 AI 插帧、GPU 直连、陀螺仪、触摸映射等尚不存在的底层能力。
- 不改变 Termux 与 Games 两种应用模式切换后必须重启的规则。
- 不以终端输出文本作为任务状态源。

## 用户可见行为

用户进入 Games 后看到横屏游戏库。点击游戏先在原页面上打开启动弹层；更多操作可进入 PC 引擎设置、修改信息、重新授权、移除和按键设置。PC 引擎设置使用左分类右内容。启动时展示“检查环境/准备环境/启动游戏”三个阶段，失败时给出可执行修复动作。进入游戏后可从右侧控制中心打开键盘、输入设置、进程管理、日志和退出确认。

## 影响范围

- 主要修改 `:games` 的 Activity、布局、横竖屏资源、字符串、drawable、UI 状态映射和测试。
- 允许调用既有 `termux-x11` Runtime API，但不修改 native/X11 协议。
- 不修改 Repository 数据格式；详情 presentation 改变不迁移用户数据。

## 风险与回滚

- 横竖屏状态：以同一 Activity 状态驱动两套资源，避免业务分叉。
- 手柄焦点：所有一级操作提供稳定 focus order，设备阶段验证 D-pad 导航。
- Dialog 生命周期：只传 game-id，重建时重新从 Repository 读取，避免持有失效对象。
- 启动错误：保留原始 error code 作为诊断信息，主界面只展示本地化修复文案。
- 回滚可恢复上一轮 Games 布局和 Activity；领域数据、任务和组件安装目录不变。
