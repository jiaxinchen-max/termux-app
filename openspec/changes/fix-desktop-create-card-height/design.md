# 设计

## 已确认根因
DesktopCreateActivity.populate 为选项设置 wrap_content 高度，item_desktop_option 根节点也是 wrap_content，内部背景图、遮罩和选择边框却为 match_parent。有限高度测量下装饰层参与父卡片的高度计算，与管理页此前缺陷同类。既有创建页回归仅验证选择内容，没有按有限视口测量卡片。

## 修复方式
使用已有 desktop_card_cover_height 作为正常 52dp 高度，GridLayout 参数显式绑定到该高度乘以至少 1 的字体倍率，避免把视口高度当成内容高度。XML 根节点也声明相同默认高度。内容区域占满明确的卡片边界，顶部区域容纳勾选和已创建标记，标题占剩余高度并在底部排列；使用最多两行、省略及现有 AppCompat 自动字号能力防止窄屏裁切。装饰层只铺满已确定的卡片。

## 模块边界与批准范围
修改新建 Activity 的卡片摆放参数、共用选项 XML 及既有渲染测试。Service、任务状态、shell、X11、输入、存储、组件下载与自动安装逻辑维持当前实现。用户对遗漏页的截图反馈作为该具体补修范围的授权。不触及签名、权限、发布或原生保护路径；未发现额外保护策略。

## 验证及回滚
在现有 DesktopCreateRenderingTest 增加 Native/PRoot 的有限 GridLayout 视口测量，使用真实图形模式验证多档宽度、视口高度及字体，断言选项没有纵向膨胀、标题/角标不交叠且文字布局可容纳。记录红绿结果。运行已有 Native 唯一性、PRoot 命名、状态恢复、自动安装和管理网格测试。构建并核验同名 arm64 APK、签名、ABI、资产、下载哈希及与前次包的内容差异。

代码与资源只回滚本次修正；已有管理页固定尺寸和菜单删除继续保留。OpenSpec/Harness CLI/脚本及产品基线文档当前缺失，如实记录，不声称严格门禁或实机通过。
