# X11 模块内部清理

## ADDED Requirements

### Requirement: 仅移除当前应用没有使用的实现

清理必须以跨模块、清单、XML、JNI、动态引用和构建入口为依据。没有当前调用方的旧模型、菜单、资源及启动资产可以移除；不能以代码来源作为删除依据。

#### Scenario: 正常使用程序会话

- **WHEN** 用户启动已有 native 或 PRoot 程序并使用 X11、控制器、手柄 API 切换或任务管理
- **THEN** 清理后与清理前保持相同入口、协议及操作行为
- **AND** 不增加初始化、网络下载、数据迁移或运行时回退

#### Scenario: 动态加载控制器内容

- **WHEN** 用户打开控制器配置、图标选择或 X11 设置
- **THEN** 动态枚举的内置配置、图标及按名称读取的设置文案仍可用
- **AND** wine-bridge.exe 与全部当前支持架构的控制器 DLL 保持完整

### Requirement: 应用资源与原生构建保持有效

移除模块资源后，完整应用必须成功完成资源合并、资源链接和 Java/原生编译。移除原生源必须证明没有构建入口和 JNI 宿主。删除的旧菜单资源 ID 不得遗留在活动代码。

#### Scenario: 构建并安装清理后的应用

- **WHEN** 构建既有 arm64 debug 应用
- **THEN** 构建和已有相关回归通过，无资源缺失或类型缺失
- **AND** 继续使用原 APK 名称和签名，不设置 testOnly

#### Scenario: 发现候选仍有实际引用

- **WHEN** 实施中发现清单候选被当前功能或构建引用
- **THEN** 保留该候选并更新证据，不以替换功能或隐式回退掩盖引用问题
