# 设计

用 DesktopDisplayPolicy 管理固定分辨率、刷新率及 GNOME 限制；界面共用显示行绑定，固定项不可打开无意义的单项菜单，并就地解释原因。现有固定分辨率和默认值保持兼容，保存 native 符号时不覆盖为设备尺寸。

渲染器继续复用现有 DesktopRendererPolicy，两种界面统一禁用仅一个选择的设置行并隐藏箭头，避免 XFCE、GNOME、Hyprland 的只读能力看起来可修改。

Native 在会话窗口首次布局后解析为像素尺寸，显示视图和启动 spec 使用同一数值。准备及存档恢复可使用默认数值几何生成静态配置；实际启动只原子更新输出 spec，不调用安装、初始化或包探测。重新进入活动会话从当前 spec 读取原尺寸，避免窗口旋转造成错配。本次不承诺运行中动态调整合成器大小。

GNOME/Hyprland 准备结果只放宽数值几何的匹配，刷新率、身份、渲染器、主题、USB 等仍严格匹配。Hyprland 使用运行参数设置 AQ_ANDROID_WIDTH/HEIGHT；GNOME 在锁内从准备脚本生成只替换已验证数值输出参数的本次启动脚本，兼容旧准备结果，原准备配置及用户配置保持不变。尺寸必须符合后端边界，非法输入失败而非静默回退。

影响限于桌面 Java、受管 Python、资源和测试；无注册保护路径。回滚撤销本次代码，Native 配置需先在设置切回固定分辨率；不删除容器或用户文件。用模型/仓库往返、创建/设置交互、活动会话重入、实际启动参数、准备缓存几何变更及非几何拒绝测试验证。仓库缺 Harness 脚本与 OpenSpec CLI，严格门禁如实记录不可用。
