# 文件浏览器新增创建工具与应用选择

## 需求和目标

用户要求在文件浏览器工具栏增加新建工具，并在打开文件前选择处理应用。本方案将“新建文件／文件工具”理解为“新建文件／文件夹”，在工具栏提供“新建”按钮，下拉选择两种类型；点击既有“打开”操作时始终进入 Android 系统应用选择器。

## 用户可见行为

- 工具栏新增仅显示加号图标的“新建”入口，不显示文字，名称保留为无障碍提示；展开提供“新建文件”和“新建文件夹”。进入实际目录后可用，首页三个固定入口列表中不可用。
- 输入名称并确认后，在发起新建时所在目录创建空文件或单层文件夹；取消不创建。同名或非法名称提示错误，不覆盖、不自动改名或添加扩展名。
- 新建使用既有串行文件操作任务和忙碌提示；完成后刷新目录，失败明确显示原因。三个固定根目录允许在其内部新建子项，根目录本身保护不变。
- 文件和目录菜单的“打开”每次先弹出系统应用选择器，即使已经设置默认处理应用。按 MIME 筛选候选应用，取消不打开。没有对应应用时由系统显示无可用应用或显示启动失败提示。
- 文件短按详情、长按项目操作、目录短按浏览、导入游戏、隐藏项偏好保持现有行为。空白长按仍无菜单。

## 范围和非目标

仅修改内嵌文件浏览器、文件创建辅助方法、工具栏资源和外部打开调用。不是文本编辑器，不新增重命名、多选、压缩、文件写入授权或默认应用管理。不修改 Wine、prefix、组件、shell 或游戏启动流程，不考虑旧数据迁移。

## 文档和审批

api_docs 为 N/A：无 HTTP 契约变更。product_docs 为 Required：用户可见创建和打开流程变化，验收后维护 `docs/product/file-manager.md`，一致性 Pending。既有规划 `add-file-browser-operations` 描述默认应用直开，本方案明确替代该条行为。用户已回复“批准，记得使用图标而不是文字”，确认新建文件／文件夹及应用选择器方案，同时要求工具栏使用图标；据此直接实施，不重复索取确认。

## 风险和回滚

新建操作只创建不存在的直接子项，避免覆盖既有文件；所有外部应用访问沿用临时只读 URI 授权。回滚恢复工具栏、创建方法与原打开调用，用户已经创建的文件不会自动删除。无需 Manifest、Provider 注册或权限放宽。Harness 引导及严格脚本、OpenSpec CLI、产品基线缺失，保留本地规划与审查，不声称门禁通过。
