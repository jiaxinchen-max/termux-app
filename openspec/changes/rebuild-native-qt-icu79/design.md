# 设计

## 证据

设备 readelf 确认 libQt6Core.so.6.12.0 需要 libicui18n.so.78 和 libicuuc.so.78；设备 libicu 为 79.1。指定编译机现有前缀及配方仍使用 ICU 78.3，Qt 和 KWin 的源码、构建缓存及历史定制补丁均存在。

## 候选构建

仅在用户指定 SSH Termux 编译机交叉编译和处理依赖，目标为 Android Bionic aarch64，前缀维持 /data/data/com.termux/files/usr，不使用 glibc 或 PRoot 编译产物。用户明确要求使用既有 /workspace/termux-packages/build-package.sh 自动下载依赖，编译机代理为 http://172.17.0.1:7897。停止此前手动下载、解包和传输 ICU 的方案；不使用跳过依赖下载的 -c 或 -s 模式。

使用专用候选配方和独立构建目录，保留现有源码与历史补丁。标准工具链设置自动恢复 NDK 挂载；依赖下载及解包均交给原脚本，通过保留现有前缀的依赖安装选项及必要的当前仓库版本选择参数完成。代理超时须先确认配置和实际传输，不能悄然切换手动依赖方案。安装通过 DESTDIR 暂存，输出写到候选目录；记录自动依赖安装对编译前缀的影响。不把宿主交叉工具误作为 Android 运行库。

保留 Qt popup RTTI、Native AHardwareBuffer 客户端、KWin 显式渲染与已发布修复。优先重新构建相同源码和配置；需要更改业务源码才能继续时，先补充变更范围并确认。旧源码、缓存和生产包保持可恢复。

构建结果检查 Qt 的 ICU 79 DT_NEEDED，并扫描候选及定制组件是否残留 ICU 78 依赖。拟议包依赖为 libicu (>= 79), libicu (<< 80)，实际生成方式待候选结果确认。保持现有 Qt 功能版本，不引入版本号驱动升级或运行失败回退。

用户本轮已授权更新原组件仓库及编译 APK：验证通过后替换 jiaxinchen-max/kwin 的 termux-hwaccel-6.6-r28 中实际变化的 Qt 资产，保持组件版本和文件名，并同步当前 App 下载与文件指纹清单。先上传暂存资产并验证，再交换名称；旧资产在公开下载复核成功前保留以便回滚。仓库资产索引和 SHA256SUMS 同步真实产物，历史 UI 验证结论不得扩写为新版已通过。若交叉工具与本次 ICU 修复无关且出现额外构建内容，先检查并移除非必要打包内容。设备安装仍由用户手动执行，Git 提交推送未授权。保留旧依赖清单、源码与构建备份；工具链挂载按原构建环境恢复，不删除旧缓存。
