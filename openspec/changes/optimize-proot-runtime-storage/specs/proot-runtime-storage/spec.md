# PRoot 运行库存储规范

## Purpose

将共享基础环境与可选 Wine、翻译器及 DX 组件的生命周期分开管理，减少重复安装与无关下载，并通过版本冻结、全新安装发布校验、任务排他和完整备份保持新布局的可运行性与恢复能力。

## ADDED Requirements

### Requirement: 基础环境仅准备必要组件

系统 MUST 保留默认 Hangover 与必要 Debian 运行依赖，MUST 按用户所选配置准备额外 Wine、翻译器和 DX 组件，MUST NOT 为构建基础环境强制安装全部可选版本或预热全部模板。

#### Scenario: 仅构建默认基础环境

- **WHEN** 用户显式构建新的 PRoot 基础环境
- **THEN** 安装默认 Hangover、必要系统库、中文字体与 GBK 支持
- **AND** 不因可选 Wine/Proton、Box64 或 DXVK 尚未安装而判定基础环境损坏
- **AND** 不下载未被本次准备任务选择的可选组件

#### Scenario: 准备另一套 Wine

- **WHEN** 用户保存并准备选择 Wine 10 或 Proton 11 的配置
- **THEN** 持久任务准备该配置需要的精确 Wine、翻译器及 DX 组件
- **AND** 已就绪的共享基础环境不被重建，其他配置保持原版本与前缀

### Requirement: 同一可选运行库版本只保留一份完整实体

系统 MUST 复用私有组件目录内同一身份的已校验版本，向游戏、初始化及维护会话提供一致的 guest 视图；MUST NOT 为每个消费者或共享 RootFS 再复制完整运行库。

#### Scenario: 多个游戏使用相同版本

- **WHEN** 两个 PRoot 游戏选择同一 Wine 或 Proton 制品
- **THEN** 两者引用同一份完整运行库实体
- **AND** 每个游戏仍拥有独立可写前缀和 home
- **AND** 消费过程不修改已校验组件内容

### Requirement: 运行依赖冻结到不可变版本身份

每次准备、启动与维护任务 MUST 冻结组件 ID、版本、摘要及对应私有版本目录，验证内容根与挂载目标；MUST NOT 通过启动时重新读取 active 指针悄悄换版本，或信任公共可写目录与用户环境变量提供的绑定。

#### Scenario: 下载新版本期间旧游戏运行

- **WHEN** 某组件 active 指针在另一个游戏运行期间更新
- **THEN** 已准备或运行任务继续使用原冻结版本
- **AND** 原版本不被更新或清理任务删除

#### Scenario: 版本目录缺失或路径越界

- **WHEN** 冻结目录缺失、身份不符、符号链接逃逸或绑定目标不在允许集合
- **THEN** 执行 PRoot 前报告可恢复的依赖错误
- **AND** 不切换到其他版本、后端或渲染器，也不接受任意挂载

### Requirement: 下载与准备由持久任务管理

额外组件下载和准备 MUST 使用已有可见的持久任务能力，支持进度、取消、失败重试及进程恢复；MUST NOT 在普通启动链中隐式下载或重建基础环境。

#### Scenario: 准备中取消或进程重启

- **WHEN** 用户取消首次运行库准备或 App 进程在准备中终止
- **THEN** 根据持久任务明确呈现取消或可恢复状态
- **AND** 原已就绪配置、组件、C 盘与基础环境保持可用

#### Scenario: 离线启动缺少运行库

- **WHEN** 用户启动尚未准备相应组件的配置
- **THEN** 显示依赖未准备及可重试的准备入口
- **AND** 不发起隐藏下载或执行 wineboot

### Requirement: 外置运行库进入离线备份闭包

新的基础环境备份 MUST 包含备份时已就绪 PRoot 绑定需要的外置运行库版本、身份、校验资料与基础环境；相同身份只归档一次。恢复 MUST 在发布前校验完整依赖闭包，MUST NOT 将缺失外置库的环境宣称为已就绪。

#### Scenario: 在空组件目录离线恢复

- **WHEN** 用户在没有源组件、没有网络的设备上恢复完整新格式备份
- **THEN** 所有备份时已就绪绑定的运行库恢复为可引用的私有版本
- **AND** 基础环境和这些绑定能够通过预检，不依赖原设备绝对路径
- **AND** 若未包含模板，则仅在后续实际准备时生成所需模板

#### Scenario: 备份缺少依赖或归档路径恶意

- **WHEN** 归档中的外置运行库摘要不符、数据缺失、路径越界或链接逃逸
- **THEN** 恢复在替换当前环境前失败
- **AND** 不回退为联网补齐并假装完整恢复，原环境与组件指针保留

### Requirement: 全新安装不承担旧测试数据迁移

本轮 MUST 按用户授权以全新 PRoot 安装为交付边界，MUST NOT 将旧配方、旧任务、旧模板、旧备份或旧自定义实体的兼容迁移作为安装前提。清除旧测试环境后无需保留其 previous；新构建仍 MUST 完整验证后发布，失败或中断 MUST NOT 将半成品标记为就绪。

#### Scenario: 重置测试环境

- **WHEN** 按本次用户授权清理旧 PRoot 环境
- **THEN** 删除旧基础环境、旧模板和失效准备状态，记录范围和实际空间变化
- **AND** 保留可复用组件源、Native 和宿主工具，不要求备份或迁移旧 PRoot 数据

#### Scenario: 首次构建失败或中断

- **WHEN** 全新布局构建、依赖校验或发布失败或进程终止
- **THEN** 半成品不通过就绪检查，任务允许重试或清理自身暂存
- **AND** 不要求恢复已获授权删除的旧测试 RootFS

#### Scenario: 提供旧格式备份

- **WHEN** 用户尝试恢复旧内嵌布局归档
- **THEN** 可以明确报告不支持该格式并要求重新准备
- **AND** 不静默将其当作新布局或宣称依赖完整

### Requirement: 清理与更新保护所有运行引用

系统 MUST 在准备、启动、维护、备份恢复与清理之间提供一致引用与互斥边界；仅经显式操作清理无引用的可再生数据，MUST NOT 删除仍被配置、任务或新布局备份事务引用的版本。

#### Scenario: 试图清理仍使用的版本

- **WHEN** 某版本仍被游戏绑定、活动任务或未完成事务引用
- **THEN** 清理拒绝删除该版本并说明占用
- **AND** 已运行会话和后续原版本启动均不受影响
