# Wine 运行库制品规范

## Purpose

为 Hangover 和 Wine 运行库提供可追溯的精简制品，降低安装体积，同时保留调试能力、混合架构加载信息及现有兼容行为；候选包只有在完整性与运行验证通过后才能替代已发布输入。

## ADDED Requirements

### Requirement: 制品精简保留来源和独立调试资料

打包系统 MUST 从摘要固定的输入生成独立候选运行库和符号包，记录输入输出摘要、工具版本、处理清单与体积口径；MUST NOT 原地修改源包或设备已安装运行库。

#### Scenario: 生成精简候选包

- **WHEN** 操作者以固定 Hangover 源码、构建环境、工具链和必要的摘要固定复用组件构建候选
- **THEN** 输出独立运行包、符号包和可复核的处理报告
- **AND** 报告区分压缩下载字节、解包文件字节与设备分配空间
- **AND** 原输入字节保持不变，PE 的 CodeView GUID/age 与独立 PDB 匹配，ELF 调试资料能够映射到对应候选二进制

#### Scenario: 不支持的二进制或工具失败

- **WHEN** 工具不能识别某个 PE/ELF、符号提取失败或处理结果无法验证
- **THEN** 本次制品生成失败且不发布候选为正式包
- **AND** 保留原可用制品，不通过跳过错误宣称完整精简成功

### Requirement: 精简不改变运行库兼容身份

候选包 MUST 保留需要的运行代码、资源、导入导出、重定位、异常展开、Wine builtin 标记、ARM64X 混合架构信息及 ARM64/i386 兼容组件；MUST NOT 为减小体积删除功能 DLL 或擅自更改对齐约束。

#### Scenario: 验证混合架构运行库

- **WHEN** 候选包完成精简
- **THEN** 静态检查确认上述加载信息、架构与能力清单完整，源码重编译不以旧 DLL 字节相等为验收条件，并在隔离环境验证 wineboot、32/64 位测试程序、渲染及手柄集成
- **AND** 未完成的设备或 ABI 验证明确记为未验证，不冒充已通过

### Requirement: 正式制品身份独立且可回滚

系统 MUST 为改变字节的精简制品提供独立可校验身份，MUST NOT 覆盖旧 Release 字节或复用旧摘要；只有最终来源可访问并经过校验后，组件目录才能指向该制品。

#### Scenario: 候选包尚未发布

- **WHEN** 精简候选只存在本地或尚无正式可访问来源
- **THEN** 正式组件索引继续使用原包
- **AND** 本地报告准确列出候选和待发布状态，不写入虚构下载地址

#### Scenario: 候选包未通过兼容验证

- **WHEN** 加载或运行回归失败
- **THEN** 不激活候选包，旧版本与其调试资料仍可使用
- **AND** 记录失败证据与候选身份以便复现


### Requirement: 自编译测试组件使用真实独立分发身份

在本轮用户明确授权的测试阶段分发中，系统 MUST 使用 pdb2 独立版本及其真实 URL、size 和 SHA；发布说明 MUST 分别记录已通过的 App 初始化、图形、32/64 位与退出证据及尚未完成的 ABI、手柄和完整回归。MUST NOT 以此次发布冒充全矩阵验收或覆盖旧资产。

#### Scenario: 安装自编译测试版本

- **WHEN** App 按更新目录准备全新 PRoot 基础环境
- **THEN** 下载并校验 v2 的 pdb2 运行包，通过原 Debian 安装流程使用自编译 Wine
- **AND** 新组件摘要参与配方和模板身份，符号包不成为设备运行依赖，Native 选择不受影响
