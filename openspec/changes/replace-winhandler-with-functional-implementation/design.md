# 设计

## 职责与产物

使用 C／Win32 实现，按报文编码、Windows 操作、启动生命周期分层。现有 EXE 为 x86-64 PE；第一份候选保持同架构、文件名 wine-bridge.exe、安装位置 C:\windows\wine-bridge.exe。构建记录工具链与导入库，输出剥离调试信息的运行文件，调试符号作为独立构建产物保留。编译结果是 Wine 直接加载的 Windows 程序，不分 native-glibc 和 proot 的 ELF 版本。架构校验及导入检查是发布前必要验证。

## 命令和协议

以调查报告的具体字节偏移作为双方契约，保留 7946／7947 端口和64字节基础报文。Windows 端仅绑定回环地址。长度检查按每种指令的真实字段进行，键盘、鼠标和进程回复的头格式并不统一；不根据任意声明长度进行未经界定的复制。发送缓冲区清零，显式逐字段写入，避免结构体填充及尾部未初始化字节。

启动握手、退出、运行程序、枚举进程、按名终止、按PID或名字设置亲和性、键鼠注入、位置反馈、按名字或HWND置前各自对应现有命令。不存在的目标及系统调用失败留可见诊断，不返回虚假成功。未知／不完整数据报拒绝处理，不执行截断命令；合法后续报文仍能工作。当前协议没有通用错误回包，本次不擅自发明错误报文或默认行为。

现有 Android EXEC 大于64字节会被发送截断；按当前接口先明确拒绝截断请求，不假装支持长命令。命令行直接启动的长度不受UDP64字节限制。若后续要支持更长UDP命令，作为另行确认的双方协议变更。

## 启动和退出

支持显式 Windows 程序路径、程序参数、/dir 工作目录、/affinity 十六进制掩码。命令行解析须正确保留带空格和引号的参数，不能为复刻原版而重新引入丢失引号。项目启动脚本已传入目标，不增加原版无参数自动启动 wfm.exe 的分支；缺少目标时直接报错退出。

必须先建立服务并完成必要本地准备，再启动目标，准备或CreateProcess失败终止。目标以及它实际派生的游戏进程结束后自然退出，不用固定超时强制结束正常游戏，也不将系统中新出现的较大PID视为本游戏。实现阶段先在现有Wine验证进程组／Job支持以及启动器派生链，选择能通过真实生命周期用例的追踪机制；如果运行时不支持，作为明确未完成项处理，不能改回近似PID算法或声称完成。结束时关闭套接字和线程句柄。原EXE保留在构建证据目录供人工回滚，不作为运行时后备。

## 手柄边界

不修改 dinput／xinput DLL、Android GamepadHandler 或现有控制器保存逻辑。原 EXE 并不代理手柄GET_GAMEPAD／STATE请求，替代版也不抢占DLL端口7948／7949。

## 集成、影响及回滚

确认后新增可重建的 Windows 程序源码／构建脚本、协议测试及集成测试，再用验证过的候选新增 termux-x11/src/main/assets/wine-bridge.exe，移除旧 winhandler.exe，安装器和两条启动链统一使用新名称；如发现任何实际启动路径依赖未覆盖功能，先更新方案再实现。二进制是运行关键路径：替换前需已有规划及关键资产批准，影响是所有Wine游戏的启动和运行时管理，验证覆盖两条启动脚本和四类运行时。人工回滚仅还原该资产及本次源码／构建改动，不撤销工作区既有修复，不修改组件版本、DLL或prefix。

## 验证分层

1. C协议层：真实Java编码样本、固定偏移回复、错误长度、未知指令及无未初始化数据；使用ASan／UBSan（本机协议核心）检查越界。
2. Wine集成：使用真实PE探针创建窗口／子进程，验证带空格参数、工作目录、自然退出及启动器派生、失败退出、列出进程字段、终止、亲和性、按键和鼠标事件、窗口恢复置前。
3. 原启动链：PRoot与Native脚本现有集成测试、相关Java测试、候选PE类型／导入与APK载荷检查、正常APK构建。未具备Wine运行环境时明确记录阻塞，不用桩测试替代运行验证结论。
4. 用户手动验收：Wine9.3、Proton、PRoot普通Wine和Hangover下实际启动退出、运行时管理及手柄功能。完成前不定稿产品文档或归档。

## 已确认后的具体实现

用户明确同意替代并命名为 wine-bridge。入口使用 CreateProcessW 的挂起创建，加入带完成端口的 Job 后恢复；Job 的自然空事件决定结束，无正常游戏超时。Job 设置关闭时终止所属进程，EXIT 或异常退出关闭桥接时一并清理该组，不影响无关进程。UDP EXEC 仍保留 ShellExecute 的系统打开功能。所有安装及启动位置使用 wine-bridge.exe，不保留旧命名入口。

实测Wine 10接受Job亲和性配置但未应用掩码，因此在恢复挂起的目标之前显式调用SetProcessAffinityMask，由子进程正常继承。Job仍只负责归属及自然结束通知，亲和性设置失败直接终止启动。
