# 卡片创建时间顺序

## ADDED Requirements

### Requirement: 两类内容卡片采用稳定创建时间倒序

系统 MUST 为 Wine 游戏记录和 Desktop 桌面记录保存创建时间，并在 Native／PRoot、网格／列表中按时间降序显示；时间相同 MUST 按稳定 ID 升序。新增及导入动作卡 MUST 保持现有入口位置。

#### Scenario: 创建与导入新卡片
- **WHEN** 用户创建、导入或恢复为一条新记录后返回所属列表
- **THEN** 新记录排列在较早创建的记录前面，切换网格／列表或重启 App 后顺序一致。

#### Scenario: 编辑、启动和重新安装
- **WHEN** 用户重命名、更新运行配置、启动、重新安装同一条目或刷新列表
- **THEN** 条目创建时间保持不变，不因文件修改时间变化跳到最前。

#### Scenario: Desktop 状态与固定入口
- **WHEN** 桌面顺序改变、补全 Native 固定入口或反复切换模式
- **THEN** 会话状态及操作仍绑定正确记录，现有固定入口不丢失／重复，已存在入口的创建时间不刷新。

### Requirement: 缺失历史时间仅补齐一次

系统 MUST 接受缺少创建时间的现有记录，首次补齐使用补齐前的记录文件时间；无法取得有效文件时间时使用稳定值 `0`，MUST NOT 冒充精确历史或在每次加载时重新取修改时间。

#### Scenario: 旧记录升级及之后编辑
- **WHEN** 旧记录首次加载后重新加载或修改名称
- **THEN** 补齐时间保持固定，补齐采用原子发布，不损坏原记录；持久化失败明确报错。
