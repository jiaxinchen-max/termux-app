# 设计

## 边界与现状

界面属于 `termux-ui` Android XML／Java 模块，实际应用回归位于 `app/src/test`。Wine 经 `GameLibraryRepository` 获取游戏记录，Desktop 经 `DesktopTasks` 获取桌面及其会话状态。排序放在持久化读取层，界面筛选保持其相对顺序；Desktop 的状态必须继续与原记录绑定，禁止只排序记录却漏排状态。

本轮不调整 TermuxService 进程树退出逻辑、输入映射、组件索引、下载资产或 X11 桥接安装。仓库未提供 Harness 引导四文件、保护路径注册表、标准产品文档、基线规格、OpenSpec CLI 或严格脚本；按现有变更目录编写计划并如实记录工具限制，不虚构门禁通过。

## 一、持久化创建时间与稳定排序

- 为 `Game`、`DesktopDistro` 及其文件编码添加毫秒创建时间；所有 `with*`、启动后更新、设置编辑和恢复复制路径必须明确保留旧记录时间或为新记录创建新时间。实现时保留现有构造入口的源码兼容，不将读取时间当作创建时间。
- 新记录首次成功发布时确定时间，后续保存以已持久化记录为准，避免调用方使用旧构造器误将其刷新。失败发布不得留下半条排序记录。
- 旧记录缺字段时，在覆盖文件前读取既有文件时间；补齐通过原有同目录临时文件原子发布，并置于仓库的现有互斥范围内。零或不可用文件时间使用稳定兜底值 `0`，不使用当前时间冒充历史。补齐写入失败必须显式报错并保留原文件，不宣称迁移完成。
- 排序为创建时间降序、ID 升序。一次刷新只加载一次列表；网格、列表和后端筛选共用同一数据序列。固定 Native 桌面仍按当前 `DesktopCreationCatalog.nativeOptions()` 补齐，不以历史提案中的已退役桌面类型扩大范围。
- 新建、导入、恢复为新 ID 的记录采用当前创建时间；重新安装同一 ID、已有固定入口补全检查和任意属性修改保持原时间。新增／导入动作卡维持现有位置，不冒充内容记录参与排序。

## 二、Wine Native 分辨率贯通

### 配置与显示

引入可复用的尺寸选择／数值验证策略，复用 Desktop 对“窗口原生尺寸”的语义和显示文案，避免将 Desktop 的 GNOME 刷新率规则耦合到 Wine。Wine 固定预设、已有自定义尺寸和默认值保留，只增加 `native`。常用页、菜单摘要、保存与重建均显示本地化标签，配置仓库仍保存 `native`。

### 在冻结任务前取得窗口尺寸

实际生产启动调用集中在 `GameLaunchActivity`。对于新 Native 任务，该入口先应用与 `GameSessionActivity` 一致的游戏方向、沉浸状态和刘海窗口策略，在布局完成且有效像素宽高为正后提交启动请求。测量完整内容区域，避免用物理屏幕指标忽略分屏／窗口模式，也不能将 dp 当 px。

将本次窗口尺寸作为不可变请求传入 `PersistentLocalGameOrchestrator`；在任务锁内把请求原子持久化到任务专属文件，再发布排队任务和唤起服务。服务在组件／prefix 准备可能暂停恢复后，从该任务请求读取尺寸，在 `LaunchSpecFactory` 冻结前将有效 profile 的输出解析为数值。请求文件失败不得启动半准备任务，孤立临时文件按现有任务清理边界处理。

活动任务复用优先于重新测量；既有 `LaunchSpec` 与环境指纹继续有效，重入时不读取当前窗口覆盖它。无窗口的内部入口若请求新的 Native 会话且缺有效尺寸，明确报 `window_size_required`，不得默默回退固定尺寸或启动 shell 后才发现非法几何。固定尺寸调用继续兼容既有签名。

### Service、shell、X11 与输入

服务继续拥有进程与任务生命周期，不交由 Activity 启动 Wine。前置 prefix／rootfs 准备若需要数值几何，使用既有默认准备尺寸，不把准备尺寸写回用户的 `native` 配置；实际运行必须使用本次冻结尺寸。`LaunchSpec`、Wine 虚拟桌面、X server 输出、`X11SessionView` 和坐标映射使用同一数值。`native` 字面量不能进入需要数值的 shell 参数；环境变量尺寸覆盖也不得使实际输出与冻结尺寸不一致。Native／PRoot、直接运行游戏／打开 Wine 桌面四条路径均验证。

不改变运行中尺寸。旋转或调整窗口后重入活动会话仍用原尺寸，停止后新启动才重新测量。尺寸无效时在产生进程副作用之前提示失败。

## 三、文件浏览器多选与批量写入

### 选择交互

在实际目录工具栏添加“多选”，原单项长按菜单增加“选择”；长按空白不执行操作，首页三个固定根入口不参与选择。多选时点击项目切换勾选，显示已选数量，提供全选／取消全选、复制、剪切、删除及退出选择。已选项具有明显标记与无障碍状态；网格与列表切换保留选择。

选择以当前目录下的绝对路径快照表示，保留符号链接本身的身份，不因解析链接而扩大作用范围。全选仅包含当前可见且允许操作的条目；隐藏项开关移除不再可见的选择，目录刷新剔除已消失项目。旋转恢复时重新检查当前目录、存在性及操作权限，不能保留越界对象。返回键先退出多选，再执行原目录返回；切换目录清空选择。复制／剪切生成不可变多项剪贴板后退出多选，允许导航至其他目录再粘贴；取消剪贴板清空整批。

### 批处理执行与结果

为现有单项 `BrowserFileOperations` 增加批处理协调，单项菜单也转为单元素批次，避免两套行为。底层递归、链接、根保护和临时发布实现继续复用，不另外编写不受约束的递归复制／删除。

批次开始前固定源列表及目标目录，检查所有源可操作、目标权限、重名目标、批内同名、源目标相同、自身子树和路径边界；预检发现错误时不开始写入。执行前仍对每项再次检查，不能把预检当作锁定外部文件系统。`ioExecutor` 串行执行，单次点击仅产生一个批次，导入／写操作互斥，忙碌时禁用重复动作。

删除先显示总数和可滚动名称列表，确认后才提交；取消不写文件。运行中的批次遇到首个错误立即停止，报告完全成功、失败及未尝试项目，不能把部分成功显示为整批成功。每项复制仍先完成临时内容再发布，剪切只在目标发布成功后删除源；不承诺跨项目原子回滚。目标已发布但源删除失败时同时给出源／目标信息并要求用户处理冲突，禁止将其当作未执行任务自动重试。

完全成功的剪切条目从剪贴板移除，尚未执行条目保留；部分移动失败条目保留明确错误状态，不能直接重试覆盖目标。复制剪贴板可保留供再次粘贴。删除同时清理剪贴板中已经不存在的源。批次结束后统一刷新目录与菜单，保留现有目录观察合并刷新机制；Activity 重建继续复用原 ViewModel，销毁页面后已确认批次继续串行完成；进程退出后只提示核对源／目标，不自动重跑或冒充恢复完成。进程内只允许一个批次持有持久化请求记录，第二浏览页面不得清理活动请求或覆盖它。

共享存储继续使用 `ExternalStorageAccess`；私有目录／游戏目录／共享存储只在现有授权范围内操作。固定根目录对象及受保护祖先不能复制、剪切或删除；对这些根内部普通条目的批量操作仍允许。

## 验证与回滚

复用并扩展现有仓库、启动参数／任务恢复、`DesktopNativeResolutionTest`、`GameFileManagerOperationsTest`、`GameFileManagerBlankSpaceTest` 和 `BrowserFileOperationsTest`。覆盖三个独立能力的行为断言，而非复述资源字符串。真实数据写入验证只使用临时测试目录；不在用户现存容器或游戏上执行批量删除。

构建保持普通 arm64 debug APK 原名、原签名，检查最终 manifest 无 `testOnly`、唯一 ABI、ZIP／签名与下载内容。严格脚本缺失时记录 Unavailable，不标记通过；用户设备安装不在本轮预授权范围内。

未发现适用保护路径 policy id；计划涉及启动编排、文件删除协调及仓库格式，仍在需求确认时列明影响：影响本地启动尺寸、元数据及用户主动操作的文件。回滚分别撤销排序、尺寸及批处理改动；回退旧解析器前备份并移除新增创建时间字段，将 Wine 的 `native` 改回固定尺寸。文件操作已完成的真实变更须由用户备份恢复，不能假称卸载或回退代码会恢复内容。
