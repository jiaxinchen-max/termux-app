# Games SAF 游戏导入提案

## 背景

组件链路已完成，但游戏库入口仍无法选择用户目录。该分片实现已安装 Windows 游戏目录的授权、受限扫描、PE 校验和主 EXE 确认，为后续游戏库与启动链提供稳定 Game 记录。

## 目标

- 通过 `ACTION_OPEN_DOCUMENT_TREE` 选择目录并持久化读权限。
- 在后台按深度、文档数、目录数、候选数和总大小限制扫描。
- 只把通过 PE 签名校验的 `.exe` 纳入候选，按目录关系、名称、大小和排除词排序。
- 展示全部候选及识别依据，允许用户手动选择、修改名称、工作目录和启动参数。
- 原子持久化 Game 记录；权限失效时给出重新授权动作。

## 非目标

- 不实现封面提取、完整游戏库、详情页、删除和启动。
- 不运行安装程序，不递归解压归档，不访问网络元数据。
- 不修改主 app、TermuxService、脚本或 X11。

## 用户可见行为

用户从游戏库点击“添加本地游戏”进入独立导入页，选择目录后看到扫描进度、限制提示和排序后的 EXE 候选。确认后保存 Game；目录权限不可用时页面阻止确认并要求重新选择。

## 影响范围

仅修改 `:games` 的 Activity、module manifest、导入领域/数据代码、资源、测试，以及对应 OpenSpec/Harness/领域文档。

## 风险与回滚

- 大目录：有界扫描且运行在后台线程，Activity 销毁中断并忽略旧结果。
- 恶意/异常 Provider：校验列值、URI、PE 偏移和扫描计数，读取失败作为可解释错误。
- 错误候选：候选排序不替代用户确认，低置信/排除项仍允许手动选择。
- 回滚：删除新增导入 Activity/类/资源即可；不影响组件和现有 Termux 数据。
