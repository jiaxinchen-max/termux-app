# 设计

归档发行版策略增加 Ubuntu GNOME Resolute，导出、元数据读取与 UI 使用同一策略；保留渲染矩阵约束。其他未适配桌面不显示导出入口，服务端继续拒绝非法组合。

宿主恢复前置阶段选择已发布 GNOME50 核心和共享 Shell 支持组件，按各自原发布源获取并核对包身份；复用普通安装的 launcher 安装函数。公共 Python、PRoot、音频及自定制 API 登记保留。此阶段不得运行容器包管理器、重装容器或安装无关 KWin/Xlorie。

恢复初始化用最终桌面身份、最终 alias、正式 pid/ready 路径、分辨率、刷新率、渲染 socket；为 GNOME 接通现有纯本地初始化，并在准备前删除新恢复容器内受管理的旧会话工作区，重新生成指向新 alias 的脚本和 runtime 链接。保留该工作区之外的用户文档、配置、dconf、软件包数据库和扩展。恢复初始化成功后，以独占临时文件、持久化 inode 归属和不可覆盖发布写入正式启动 spec，再发布桌面记录；失败按同一归属清理 spec。此步骤同样覆盖 XFCE/Plasma，避免移除启动初始化后恢复记录缺少正式 spec。任何初始化失败阻止发布记录并走原事务清理。音频在恢复准备阶段配置，启动路径无新增探测或修复。

归档排除 GNOME 受管理会话工作区及虚拟挂载目录内容，仅保留目录节点；不跟随 rootfs 内链接。既有格式允许该目录为空，恢复总是重新生成会话。归档写入/读取均使用相同规则。重名处理复用 DesktopRestoreNames。

高风险路径为归档引擎排除策略、恢复调度和安装脚本；用户本轮批准前述完整链路修复。无机器保护策略文件可用。风险是误删用户配置、旧身份引用或缺失宿主组件；定向测试覆盖并用独立恢复身份验证，保留原容器和原备份。回滚仅撤销本变更源文件，用户原数据不变；保留已有七个第三方子模块脏改动。

验证包括发行版/元数据允许及拒绝、真实文件归档往返和名称保留、旧运行状态排除、GNOME 宿主前置无容器调用、恢复参数与最终启动参数一致、初始化失败不发布、既有 Plasma/XFCE 回归、Android 编译；设备测试前 force-stop App，使用独立恢复目录和原组件。不能完成的实机步骤明确记为待验收。无需重新编译外部 DEB。
