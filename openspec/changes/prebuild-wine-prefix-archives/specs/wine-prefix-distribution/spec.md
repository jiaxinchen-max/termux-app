# 预生成 Wine 前缀分发

## Purpose

让用户首次准备游戏时能够按运行库与架构获取已经初始化完成的干净前缀，通过受控解压得到独立可写 C 盘，避免在测试设备执行重复而缓慢的全量初始化，并保持组件身份、完整性、取消恢复与已有数据保护。

## ADDED Requirements

### Requirement: 前缀制品按完整运行身份区分

预生成前缀 MUST 绑定宿主 ABI、运行后端、Wine 二进制身份、翻译器身份、prefix 架构、基础兼容配方和初始化修订。相同架构的不同运行库 MAY 复用已验证兼容的初始化骨架，但最终恢复清单 MUST 绑定所选运行库系统文件及完整身份，不得共用不匹配 DLL；WoW64 模板 MUST 同时保留其所需的 32/64 位内容。

#### Scenario: 准备当前自编译 Hangover

- **WHEN** 用户准备具有匹配预生成制品的 PRoot/aarch64/WoW64 Hangover 配置
- **THEN** 系统选择该精确身份模板并支持其 32/64 位程序
- **AND** 不下载其他架构模板，也不替换为 Native 或另一版本 Wine

#### Scenario: 组件字节或配方变化

- **WHEN** 运行库摘要、翻译器、后端、架构或初始化配方变化
- **THEN** 系统拒绝以原身份模板初始化新配置

### Requirement: 制品只来自已完成初始化的干净前缀

构建流程 MUST 在受控环境等待一次初始化及其安装注册子任务完成，确认注册表和所需系统文件有效、Wine 进程已安全退出后才打包。MUST NOT 包含游戏、凭据、构建机个人文件、进程套接字或设备私有绝对路径；固定等待超时不代表成功。

#### Scenario: 构建初始化尚未结束

- **WHEN** 初始化报启动事件超时、子安装仍活动或目标文件不完整
- **THEN** 构建不产出可分发成功制品及就绪声明

#### Scenario: 跨环境解压

- **WHEN** 新设备在不同宿主绝对目录使用通过验证的前缀包
- **THEN** 前缀不依赖构建机路径且中文、32/64 位 smoke 可运行

### Requirement: 新游戏准备只消费预生成制品

已声明预生成支持的 Hangover、普通 Wine 10.0 与 Proton 11.0 配置 MUST 在显式准备任务中校验和解压前缀，不执行设备端全量 wineboot，不生成重复 `--init` 与强制 `-u` 安装。缺失、不匹配或损坏时 MUST 明确失败，MUST NOT 静默回退到本地构建。

#### Scenario: 第一个新游戏

- **WHEN** 设备无本地模板但所选组件提供有效预生成包
- **THEN** 准备完成校验和解压并发布该游戏就绪状态
- **AND** 不执行全量安装注册或强制更新

#### Scenario: 缺少或损坏预生成包

- **WHEN** 所选预生成组合的包缺失、摘要不符或结构无效
- **THEN** 显示可重试的明确错误且不发布半成品
- **AND** 不切换 Wine、不触发隐藏初始化

### Requirement: 解压只写入私有且经过校验的暂存目录

系统 MUST 验证归档条目、大小、路径、链接与身份后，在任务私有 staging 解压并核对注册表和必要 DLL，成功后原子发布；每个游戏使用独立可写副本。系统 MUST 拒绝越界条目、危险链接、空间不足或覆盖非空游戏 C 盘。

#### Scenario: 恶意归档或空间不足

- **WHEN** 归档含目录穿越、借助链接写出目标或声明/实际体积超限，或者设备空间不足
- **THEN** 准备失败，现有组件、模板和游戏文件保持不变

#### Scenario: 取消和并发

- **WHEN** 两个请求需要同一模板，或任务在解压期间被取消/终止
- **THEN** 同身份缓存只安全发布一次，每个游戏保持独立副本
- **AND** 未完成目录不被标为就绪且重试不无限等待

#### Scenario: 已有游戏目录非空

- **WHEN** 新模板准备目标已包含未经确认的游戏数据
- **THEN** 系统保留文件并提示显式处理，不覆盖解压

### Requirement: 正常启动不触发前缀全量安装

正常游戏启动 MUST 只消费已准备前缀；它可以运行 Wine 正常服务启动，但 MUST NOT 因模板时间戳、缺少初始化记录或制品身份错误而重新执行全量安装注册。初始化进度、取消、下载和解压 MUST 在显式准备任务中可观察。

#### Scenario: 解压后启动及复用

- **WHEN** 用户启动新准备的游戏或第二个相同身份的游戏
- **THEN** 两者使用各自 C 盘且不再次全量 wineboot
- **AND** 前缀制品摘要保持不变，普通启动不承担模板下载或重建

### Requirement: 小模板从精确公共运行库还原

试用 APK MUST 携带干净差异归档及带 SHA256 的公共文件清单，并将其内容绑定准备身份。公共 DLL 与字体 MUST 从精确匹配的已安装 RootFS 或身份固定的外置 Wine 组件复制，校验源路径范围、类型、长度及摘要，MUST NOT 使用可写硬链接。仅在完整暂存校验后发布每游戏独立 C 盘；当前资产的实验来源和图形待验收限制 MUST 记录。

#### Scenario: 公共运行库文件不匹配

- **WHEN** 公共 DLL 或字体缺失、超出允许范围或 SHA256 不符
- **THEN** 准备明确失败、不发布半成品且不回退到全量 wineboot

#### Scenario: APK 本地试用

- **WHEN** 用户安装内嵌匹配小模板的 APK 并准备新的 Hangover 配置
- **THEN** 应用使用本地资产和公共运行库还原独立文件，无需新组件发布或额外模板下载
