# 设计

## 根因与实现
DesktopActivity.showMore 按状态添加 MENU_INSTALL，安装入口因此随状态出现或消失。删除 MENU_INSTALL 常量、items.add 分支及菜单点击处理；保留其他菜单 ID，避免无关编号变化。主按钮和创建回调直接进入原安装流程，不依赖 MENU_INSTALL。

## 模块边界
只修改 Activity 的本地菜单行为。Service、任务状态、shell、X11、输入、存储和组件下载均沿用原实现；不新增安装判定、启动预检、自动重试或文件清理。用户前文提出的安装成功/失败规则仍需独立处理；本变更不声称解决 FAILED 的安装/启动混用。

## 规划确认与保护路径
用户截图和“应该去除”的具体指令确认删除范围。未发现仓库保护策略；仅 Activity 普通源码及本变更证据，不触及签名、权限、发布、环境或高风险原生文件。现有未提交修改全部保留。

## 验证与回滚
检查源码及编译产物无 MENU_INSTALL；确认主按钮、自动安装、原安装控制台和其他菜单分支保留。运行安装任务及状态解析现有测试，构建本地 arm64 debug APK，验证签名、ABI、资产和原始文件名。删除菜单项属于可逆低影响变更，不新增照抄条件的测试。无连接 Android 设备时把界面验收列为 Pending。回滚仅恢复本次三个删除点，不覆盖其他修改。

Harness bootstrap、strict gate 和 OpenSpec CLI 当前缺失，使用仓库既有目录手工记录规划和证据，不声称严格门禁已通过。
