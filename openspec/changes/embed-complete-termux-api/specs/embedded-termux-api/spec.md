# 内置 Android API 能力

## 要求：上游完整能力和主 APK 路由
系统必须覆盖固定上游清单的全部方法与 CLI 命令，并记录实现和验证证据。命令直接调用主 APK；没有安装外部 com.termux.api 不应影响内置能力。已有 USB 功能必须保持。

### 场景：读取电池
在只安装主 APK 且会话已运行的设备上执行 termux-battery-status，应返回真实电池 JSON，调用结束后不遗留等待进程；UPower 可完成服务注册，Dolphin 不再阻塞于该请求的约 25 秒超时。

### 场景：设备或权限不满足
对无硬件、权限拒绝、系统限制和宿主不可用分别返回明确错误；不伪造成功、空电池或无界等待。

## 要求：权限、隔离与生命周期
权限按对应操作申请，敏感接口验证请求来源。异步、交互和流式操作必须能完成、取消及回收；应用退出和断线关闭资源，USB FD 传递行为保持有效。

### 场景：不可信请求
其他 UID 伪造 API 请求时，服务拒绝执行并关闭连接。

### 场景：长会话
录音、传感器及定位的有效会话不会因连接握手的短超时而被截断；停止命令或取消后资源释放。

## 要求：初始化与交付
依赖安装、CLI 路由配置与静态能力检查在保存/初始化阶段完成，不增加桌面启动预检。UPower 的实际电池刷新须有界且不阻塞服务注册。APK 保持现有包名、签名、最低 Android 版本和普通可安装属性。
