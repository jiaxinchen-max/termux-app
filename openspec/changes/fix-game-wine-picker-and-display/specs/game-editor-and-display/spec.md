# 游戏版本选择与显示需求

## 新增需求：Wine 版本选择可操作
游戏编辑页的 Wine 选择入口必须打开当前后端版本页；选择可用版本必须更新编辑配置，并在保存后保留该确切版本。取消保持原值，失败必须反馈，不得替换默认版本或切换后端。

### 场景：从两后端编辑入口选择
- 给定当前游戏属于 Native 或 PRoot，且已按既有规则终止关联任务。
- 当用户点击 Wine 版本入口并选择已安装版本。
- 则版本页可见，编辑页显示所选版本；保存使用该版本，未保存时 Launch 置灰。

### 场景：从游戏的组件入口进入
- 给定用户从游戏编辑页的组件入口打开 Wine versions。
- 当列表展示已安装 Wine/Proton。
- 则当前游戏所选项必须显示勾选与“当前选择”，其他项仅为已安装；点击其他项能选择并返回编辑页。
- 未保存的新选择不得直接写入游戏配置，返回编辑页必须显示该选择。
- 全局组件管理无当前游戏，不伪造全局已选项；Native/PRoot 归属不能在选择过程中改变。

## 新增需求：游戏画面与输入一致
游戏会话应按配置分辨率在当前可用显示区域等比显示并居中，保留正确的触摸位置。应先确认故障是整个桌面还是单个游戏窗口；不得用强制拉伸全局显示掩盖未定位的问题。

### 场景：初始显示及尺寸改变
- 给定游戏在配置分辨率下启动。
- 当显示 Surface 首次可用、重建或可用区域变化。
- 则显示区域与有效源尺寸正确匹配，整幅桌面不会因错误视口缩在左上角，输入映射使用同一坐标转换。

## 保留需求
编辑和删除不根据任务状态拒绝，先强杀再操作；仅 Launch 使用就绪门禁。不添加 prefix 重建、运行时版本回退、老数据兼容或设备后台验证。

### 场景：从 Wine 9.3 切换到 Proton 11 后重新启动
- 给定用户已经保存 Proton 11 选择，且其独立 prefix 已恢复完成。
- 当新会话启动或渲染连接重建。
- 则 X 服务启动尺寸与 Wine 虚拟桌面的目标尺寸来自同一个已解析配置；当前前台会话在连接可用后重新发送尺寸。
- 后台旧会话不得覆盖当前会话视口；整幅桌面应等比居中，输入与画面一致。
- 启动和连接日志应足以区分目标尺寸、实际 X 根尺寸和显示视口；诊断不要求用户安装工具、修改内部参数或重新初始化 prefix。
- 仅完成尺寸同步补丁或静态检查不能替代用户对截图故障的手动验收。
