# 组件显式安装管理，移除版本驱动升级

## 需求
用户否定了为补包提高组件修订号、依赖版本比较自动更新的方案，要求版本号不能改，删除所有类似的版本驱动自动升级逻辑，并为已安装组件增加卸载、安装、重装子菜单。此变更覆盖Native和PRoot的独立可安装组件；不恢复已取消的独立组件总目录入口。

## 目标行为
- 组件实际版本与ID保持不变，不为补文件提高修订号。Box64 0.4.4目录项本次从修订2恢复为原修订1，保留已发布完整包URL；URL只是下载位置，不用于推断更新。其他组件不批量改版本号。
- 已安装且可用的同一组件不因目录版本、任务版本或配置中的历史修订号差异被自动替换，也不显示可更新、强制升级或启动版本不一致错误。不同真实程序版本仍以不同组件ID供每个游戏明确选择。
- 首次缺失的依赖仍按现有保存/构建流程准备。实际文件损坏或缺失如实失败或显示未安装，不借另一个版本回退，不重建prefix来修复组件。
- 组件版本列表每个独立可安装条目增加操作子菜单。按用户最新明确要求，将Turnip/DXVK大包拆成每个候选版本一个小包；每个小包可单独下载、安装、卸载及重装，游戏选择与启动生效方式保持。已安装提供卸载、重装；未安装提供安装。选择条目与操作按钮分开，点击条目仍选择当前游戏使用的版本。
- 重装是用户明确动作：在线组件重新获取目录指定的包，不能通过旧缓存或已完成任务短路；自定义组件让用户重新选择本地包，并覆盖原ID。
- 卸载清除选中组件的实际文件、安装副本和就绪记录，停止相关执行任务，但保留游戏、配置、prefix和其他组件。自定义组件定义保留为未安装，安装时重新选择来源。
- RootFS内置Hangover属于预装环境，不伪造独立安装/卸载能力；整体环境仍通过核心组件的现有入口管理。

## 影响与文档
涉及版本列表、Native/PRoot依赖准备、启动检查、目录状态、任务去重、显式卸载及重装、激活与安装记录。api_docs=N/A：修改Android本地命令与文件操作，不增加HTTP契约。product_docs=Required，验收后创建或更新docs/product/component-management.md；当前仓库无docs/product与baseline specs，记录缺失，不声称已有文档已同步。

## 审批边界
原提案已获用户明确批准实施；后续拆包调整由用户明确提出并纳入实施。上次缺库修复及已发布资产保留；其中提高修订号触发自动替换的方案由本变更取代。不迁移旧目录，不新增摘要/签名校验。不自动提交、推送或发布APK。

## 用户实施中调整
用户明确要求大包拆小包、独立下载安装卸载，替代上轮整包管理调整。拆出5个Turnip、7个DXVK及1个VKD3D，复用原7z字节，不引入无入口的Zink/D8VK或旧桌面安装快捷方式。PRoot已有独立DXVK包不重复拆分。
