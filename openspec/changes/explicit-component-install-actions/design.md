# 设计

## 当前证据
- ComponentCatalogRepository按descriptor/active版本计算UPDATE_AVAILABLE，版本列表RuntimeComponentVersionsActivity也要求修订号相等才视为安装。
- GlibcRuntimeComponentPreparer与RootfsRuntimeComponentPreparer按版本不等触发准备；Native宿主TermuxRuntimeComponentProbe同样要求expectedVersion相等。
- LaunchPreflightEvaluator将配置、目录和安装版本差异转为不可用/不匹配问题。RootfsSetupAssetInstaller、NativePrefixAssets与激活路径还存在目录版本匹配约束，需区分内容来源选择与格式合法性。
- ComponentTasks只有enqueue/activate等命令，没有显式uninstall/reinstall。下载器按组件ID及修订号保留缓存，重装必须绕开已完成任务与旧归档。
- 自定义组件的输入在成功后会从staging删除，因此重装必须重新选择文件，不伪造存在的下载源。

## 安装身份与版本
以稳定组件ID、实际安装文件及安装记录判断可用；版本字段仅表达实际来源/构建记录，不表达升级意图。保留目录格式版本、序列化协议、真实包身份一致性和事务完整性检查，不机械删除所有名为version的字段。安装中任务与所提交输入的匹配仍按该次操作快照验证，不将目录变化变成后台升级命令。

准备流程先检查选中组件实际可用性；已安装则跳过，缺失则走原首次安装。启动使用选中ID对应的实际安装内容，不因目录修订不同触发升级或拒绝。冻结PRoot绑定保留其真实已安装路径，不能强行改为目录中的新修订并下载。用户显式重装成功后，刷新引用该组件的冻结绑定至新的实际安装副本，保留其他组件身份及prefix；绑定刷新失败则该操作失败，不回退。prefix模板缓存不因目录修订变化自动重新下载或重建已有prefix。

移除UPDATE_AVAILABLE及相关文案/分支；版本列表合并同一组件的安装信息，不同时出现已安装行和因修订不一致生成的在线行。真实版本选择例如0.2.7/0.4.4与Wine/Proton保持独立。

## 操作子菜单
独立组件包条目右侧的操作按钮弹出子菜单；按用户最新调整，Turnip/DXVK的每个候选版本拆为独立小包，条目可单独管理；状态决定可执行操作：已安装显示卸载、重装，未安装显示安装。选择行为保留。覆盖WINE、BOX64、DXVK、VKD3D、TURNIP中当前后端支持的独立组件，以及本地导入组件；环境预装内容不提供会破坏整个RootFS的假卸载项。

在线安装使用目录来源；已安装时不会通过普通安装自动更新。在线重装显式创建新操作，清理本组件相关旧下载/partial后重新获取当前来源，下载解包成功后替换所选组件；失败明确展示，不自动回退或重试，不碰已有prefix。安装失败不宣称成功；新的安装内容准备好之前保留原文件，不在网络下载之前先删运行库。

自定义重装走文件选择器，复用原组件ID、类型及后端，不生成另一个随机ID；取消选择没有副作用。卸载后保留最小组件定义以支持显示未安装条目及重新安装，清除所有安装就绪记录，不能保留假已安装状态。

## 卸载范围与执行顺序
1. 按组件ID和后端解析受影响游戏/容器及安装任务，串行停止相关进程，沿用现有强制停止规则，不根据任务表面状态跳过。
2. 取消该组件安装/激活中的任务，避免删后被异步任务立即发布回来。内部安装命令串行执行，界面保留非阻塞操作进度。
3. 删除所选组件独立实际目录、front组件安装副本、active/previous与宿主就绪收据；只操作代码明确限定的拥有路径，禁止按旧清单删除其他版本。组件激活产生的按ID解包目录同步清理。
4. 保留所有游戏与prefix、游戏的所选ID、外部下载缓存（普通卸载不清用户下载）及其他版本。后续保存所选游戏时，缺失依赖按首次安装准备。

## 验证与风险
重点验证：目录修订不同但已安装时保存、构建及启动均不升级；目录变动不下载prefix；缺失组件仍首次安装；显式同版本重装确实取到新来源而非旧缓存；卸载后列表/宿主/启动状态一致；已完成和运行中的任务均不会复活被卸载组件；自定义ID保留；多版本及Native/PRoot隔离；游戏选择不被动作菜单误触。通过针对性单元/脚本测试后构建普通arm64 APK，固定原文件名，由用户手动设备验收。

无旧数据迁移和兼容补丁。潜在风险是旧的共享文件包卸载误删和正在使用的组件被移除；用受控拥有范围、停止相关进程和隔离测试验证。回滚本次代码及目录项修改，不删除已发布的完整Box64包。Harness引导/严格脚本与OpenSpec CLI缺失，记录Unavailable，不冒充门禁通过。

## 已明确要求的拆包调整
读取真实原包，5个Turnip档案各约1.2–1.3MB，7个DXVK档案各约1.6–3.1MB，另有约1.7MB的VKD3D。使用原7z文件生成确定性tar.xz包装，每个包只含一个glibc/opt/libs/mesa或d3d中的档案。组件ID沿用native-turnip-*、native-dxvk-*、native-vkd3d，与游戏选择ID一致。新增目录项修订固定1，不以修订变化驱动升级。目录不再提供turnip/dxvk家族大包。Native依赖、宿主探测及版本列表按独立ID准备；首次启动仍解包所选7z、Turnip设ICD、DXVK复制DLL及设Wine覆盖。卸载清除单个7z、其解包目录、私有安装副本和收据，不影响同家族其他版本。保留原包作为构建输入。发布新资产仍需就绪后确认，未发布前不声称APK能网络安装新拆分包。
