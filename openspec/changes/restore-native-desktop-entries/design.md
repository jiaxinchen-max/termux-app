# 设计

管理页刷新时，通过 DesktopTasks 在现有 DesktopOperationGate 锁下补齐受支持 Native 环境记录，再加载库存与真实状态。复用 DesktopCreationCatalog 环境目录；已有同环境 Native 记录优先，不改 ID、渲染器、主题、USB、分辨率或帧率。仅缺失类型创建默认配置，ID 碰撞时选未使用 ID，Ubuntu GNOME 使用既有 60Hz 约束。直接写仓库，不走会部署脚本的 save()。

管理页 Native 不显示新增与可支持环境的删除操作；PRoot 新增/导入及删除不变，旧停用 GNOME 记录仍可清理。刷新渲染缓存仅在整次渲染完成后发布，避免失败后的相同库存阻止重试。检验空库存、部分既有配置、幂等、ID 碰撞、无安装副作用，以及真实 Activity 的网格/列表测量、模式切换和恢复。

截图中新增卡片也不可见，目前未独立复现，不能宣称已有唯一根因；用真实 Android 布局回归核对。本轮不修改安装状态机或设备环境。回滚只恢复本轮 Java 修改；自动补齐的默认记录可保留，既有配置不覆盖。未发现保护路径政策。本地 Harness 启动文件/脚本、OpenSpec CLI、产品知识基线缺失，严格门禁明确记录 Unavailable，设备验收 Pending。

## 布局回归定位补充

首次补齐库存后，日间和夜间的实际 Activity 布局仍出现卡片宽度 0。宽度变更监听器在布局过程同步重建子项，导致新子项未完成测量。将重建放到主线程消息队列，等待当前布局结束；测试按连续 Android 帧处理回调并重测，不通过强制单独测量子项掩盖问题。

扩大到既有 DesktopMutationTest 时，停用 GNOME 失败安装后状态保持断言失败（预期 stopped，实际 exit:1）。原始 DesktopTasks 和原始 DesktopActivity 独立回放得到相同失败，属于已有安装状态机问题，保持证据并不在入口修复中隐式更改。
