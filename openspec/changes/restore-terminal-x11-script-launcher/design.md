# 终端 X11 脚本启动设计

## 当前链路

TermuxActivity 创建 TERMINAL 类型的 TermuxScreenView，并通过 setTerminalIdleActions 绑定偏好、启动和退出按钮。启动回调 startX11Display 固定使用 CommandUtils.exec 在后台运行 termux-x11 :1；待机视图只有点击，没有长按回调。历史 StartEntryClient 已删除，但 StartEntry 和文件浏览器仍保留。

## 界面与状态

恢复独立的启动项控制器，绑定到 TermuxActivity 创建的终端模式 X11 待机按钮。TermuxScreenView 只接偏好与退出动作，启动按钮的单击与长按由控制器统一绑定；UI 模式不具备这些动作。

长按展示本地启动项列表、当前选择及添加、移除操作。复用现有文件选择器选择可执行文件，选择后保存并更新按钮名称。取消选择保持原值。未选择脚本时按钮统一显示中文“启动”、英文 `start`，选中后显示脚本名称；移除当前选择后恢复中文“启动”、英文 `start`。空列表单击打开管理入口；移除当前项后清除或明确调整选择，不能保留失效索引。移除只影响列表，不删除文件。

使用 home/.termux/config/.startItemEntries 存储列表和选择，复用 StartEntry 数据模型时修正重复载入、失效索引及持久化错误反馈。没有旧格式迁移、版本升级或网络读取。

## 脚本执行与 session 生命周期

单击只执行所选文件。执行前检查是普通文件且可执行；缺失、权限不足或配置读取失败需要明确提示，不回退到 termux-x11、startxserver 或其他文件。脚本路径按一个 shell 参数进行正确引用，不把文件名当作未转义命令字符串。

通过 TermuxService 创建独立终端 session，并由 Service 记录所有权，Activity 重建不会丢失关联。终端 session 随脚本自然结束按原会话机制清理；用户确认退出桌面时只杀掉本入口拥有的 session，既有 XServer 停止链路照常执行。没有 Activity 绑定时也要在 Service 侧回收结束的 session。反复点击不得创建重复的脚本 session。脚本可自行负责显示号、桌面和依赖；不分析依赖、脚本成功或失败，不新增失败控制台或运行诊断，不更改其他会话的退出规则。

## 边界

- Activity：创建、绑定和释放启动控制器，页面重建重读持久化选择。
- Service/任务：复用现有终端会话执行，不新增 Wine 构建或组件下载任务，不强杀正在运行的程序。
- shell：只执行明确选中的脚本，正确引用路径，保留实际退出状态。
- X11：使用既有连接与显示切换，不变更 JNI、服务端二进制、连接协议和显示号规则。
- 输入：不改控制器或触摸映射；长按消费事件，不附带执行。
- 存储：只有现有启动项配置；移除列表项不删除用户文件；不写 front 数据。
- 下载：不涉及网络依赖、组件安装、资产替换。

## 验证与回滚

测试需要执行真实的点击/长按事件接线，并覆盖选择持久化、空列表、取消、删除当前项、失效文件和含空格及单引号的路径。验证脚本一次执行、Service 持有、反复点击复用、Activity 重新绑定后退出回收、无 Activity 时自然退出回收及无关终端不受影响，以及 UI 待机页仍无启动动作。构建正常 arm64 debug APK，保持原文件名、签名与非 testOnly。用户继续负责 App 界面验收。

protected-path 策略文件不存在，因此 policy id 为 Unavailable，不声称已通过策略检查。预计变更 TermuxActivity、终端启动项控制器/存储、TermuxScreenView、终端待机布局与中英文文案、相关测试；用户已明确确认收窄范围后开始。回滚按文件补丁撤销，不操作用户数据。Harness 严格脚本缺失，记录本地实际验证结果，不冒充严格验证。
