# 增加 Hyprland 桌面合成器

## 目标

在现有桌面功能中加入可安装、可启动、可交互、可停止的 Hyprland，与 KWin/Plasma 并列。沿用已有 `hyprland` 存储标识，复用 Android 桌面显示、输入和控制抽屉。

## 用户可见行为（规划中）

- 创建桌面时可选择 Hyprland；支持原生桌面及 PRoot 客户端会话。两种模式的合成器均运行在原生 Termux 中。
- 原生模式同类型最多一个桌面；容器模式沿用独立容器和可重复创建规则。
- 提供默认平铺配置、可打开的终端和文件管理器，以及可从应用控制入口执行的启动操作，避免只能看到空背景。
- 首期仅开放经过 Android 后端验证的 system 渲染模式；Zink/llvmpipe 不在本次承诺范围内，也不作隐式降级。若 system 后端不可行，报告证据并重新确认方案。
- 安装、运行状态、日志、停止和再次启动均按 Hyprland 自身会话判断。不能把 KWin 启动成功或黑色首帧视为 Hyprland 成功。

## 实现范围

组件仓库新增 Hyprland 与匹配依赖的构建配方，完成 Android 图形和输入后端适配，产出可核验组件；应用接入完整桌面生命周期并编译 APK。先证明组件可运行，再开放应用入口。

## 非目标与兼容性

不安装完整 Plasma 作为 Hyprland 的隐藏后端；不要求设备 root 或直接访问 DRM；不改变现有 XFCE、Plasma、GNOME 配方和会话行为。本次不扩展桌面归档支持，Hyprland 导入导出保持明确不支持，不生成不可恢复的归档。已有 `hyprland` 标识不迁移、不重命名。

## 风险、回滚和文档

按用户指定使用 main，当前固定为 Hyprland 0.57.0 / 70ec30e71656bce5e1af3364129421a4386a69e1，使用匹配的 Aquamarine 和 hypr* 依赖，现有 wlroots 定制无法直接复用。Android EGL、缓冲区同步、输入与 Bionic 移植需要实证。组件失败时保持入口不可创建，保留日志；应用回滚可恢复占位状态并保留用户数据。详细影响、回滚和验证见 design.md。

不改变 HTTP API，`api_docs: N/A`。新增桌面能力属于产品变更，`product_docs: Required`，最终验收后维护 `docs/product/desktops.md`；当前不将规划写成已实现产品事实。
