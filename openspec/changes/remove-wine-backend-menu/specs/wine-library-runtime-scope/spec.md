# Wine 配置运行类型作用域

## Purpose

明确 Wine 在 Native 与 PRoot 分组下的导入和配置归属，让用户通过当前分组创建独立配置。配置页面只管理该配置的运行参数及组件，不提供后端转换或重复选择入口，并保持已有容器与数据独立。

## ADDED Requirements

### Requirement: 导入继承当前 Wine 分组类型

导入 MUST 沿用进入时的 Native 或 PRoot 作用域，不显示用于重新选择运行后端的菜单。同一 EXE 可以在另一分组重新导入为独立配置，不转换已存在的配置。

#### Scenario: 从两种分组分别导入相同 EXE

- **WHEN** 用户从 Native 与 PRoot 分组分别导入同一 EXE
- **THEN** 两次导入生成独立配置，各自保留所属类型
- **AND** 后一次导入不能修改前一配置的类型、参数或容器

### Requirement: 配置页面不提供运行后端菜单

导入后的配置页面和已有配置的编辑页面 MUST 不显示“运行环境后端”菜单或等价的后端子页，MUST 不允许将该配置切换为另一后端。

#### Scenario: 查看或编辑 Native 与 PRoot 配置

- **WHEN** 用户通过嵌入页面或独立 Activity 打开任一类型的运行配置
- **THEN** 根菜单没有运行后端入口，也不存在该子页的可达导航
- **AND** 保存其他设置后，配置所属后端与已有容器保持原值

### Requirement: 保留当前配置的组件管理

移除后端页面后，配置根页 MUST 继续提供组件管理入口，且作用域固定为当前配置的类型。

#### Scenario: 打开并选择运行组件

- **WHEN** 用户从配置根页进入组件管理或选择运行组件
- **THEN** 组件页面沿用当前 gameId 和后端范围
- **AND** 不得用其他后端组件的回传结果转换当前配置

### Requirement: 编辑标题下只读显示当前后端

游戏编辑页及运行配置页 MUST 在标题下方显示当前配置使用的 Native 或 PRoot 后端名称，不将其呈现为菜单、选择器或切换操作。横竖屏及嵌入与独立布局 MUST 一致。

#### Scenario: 查看和旋转编辑页面

- **WHEN** 用户打开 Native 或 PRoot 配置并切换横竖屏，或进入运行配置子页
- **THEN** 标题下显示该配置实际所属后端，名称不因列表分组或布局变化而改变
- **AND** 点击该文字不触发后端选择，其他未保存编辑保持原有行为

#### Scenario: 编辑页无法读取配置类型

- **WHEN** 游戏记录存在但运行配置缺失或不可读
- **THEN** 编辑页显示后端信息不可用，不默认标记为 Native，也不据此转换配置或重建容器
